# Slurm に流す

r995 の Slurm の待ち行列に、重い計算を 1 本ずつ流す。投げる道具は `~/.claude/scripts/slurm-run.sh` だけで、`sbatch` は
直接使わない（hook が止める。名前、ログ、見積もり、連絡先が抜けるため。ADR-0007）。

## 現在の待ち行列

!`squeue`

列は、ジョブ番号、名前、状態、経過、見積もり、始まりの見込み、連絡先（git のブランチ、投げた場所、`claude=` セッション）。
連絡先が自分のブランチでないジョブは、ほかのエージェントのもの。止めない、並べ替えない、取り消さない。

## 流すかどうか（ADR-0026）

資源で決める。時間の長さだけでは決めない。次のどれかに当たれば流す。迷ったら流す（待つだけで、誤りにはならない）。

- 多くのコア（目安で半分以上）を 5 分以上使い続ける
- メモリを大きく使う（目安で搭載量の半分以上）
- 時間を記録する測定（短くても）

1 コアの処理（テスト、lint、比べる道具）と数分のビルドは、時間がかかっても手元で走らせる。待ち行列に入れると、
ほかのセッションの長い計算の後ろで待たされる。

## 投げ方

```bash
~/.claude/scripts/slurm-run.sh -t <見積もり> <名前> '<コマンド>'
```

Bash ツールの `run_in_background=true` で実行する（ジョブが終わるまで戻らないので、フォアグラウンドは hook が止める）。

- `-t` は**分の数**（`-t 90`）か `H:MM:SS`。`25m` や `1h` は sbatch が受け付けない。上限ではなく、待ち行列の
  始まりの見込みに使う見積もりで、超えても止まらない。外れると、後ろのジョブの見込みが狂う
- 見積もりは過去の実績から決める。`~/.claude/scripts/slurm-history.sh --by-name` が、ジョブ名ごとの見積もり、実績、比
  （`RATIO`、`MAX_RATIO`）を出す。実績の 1.3 倍ほどを書く。実績のない計算は、小さい入力で測って見積もる
- 名前は `<道具>-<題材>`（`openmc-2K`、`xlc-2K-swap-water`、`vera-reference-stages`）。使える文字は英数字と `.` `_` `-`。
  ログのファイル名に使い、`squeue` でも見分けるので、題材が分かる名前にする
- コマンドは投げたときのディレクトリで、`--export=ALL`（今の環境変数、nix の開発シェルの PATH を含む）で走る。
  r995 以外のホストでは `~/r995`（r995 の `~/github` の NFS）の下で投げる
- 出力は `JOB:`、`LOG:`、ログの末尾 20 行、`EXIT:`。終了コードはジョブのもの

## 順番

優先度の重みはすべて 0 なので、投げた順（ジョブ番号の順）に走る。後から割り込ませる手段はない。

- 短い見積もりのジョブは、長いジョブより先に投げる。投げ終えたあとの並べ替えはできない
- `--top`（`scontrol top`）と Nice は、この設定（優先度の重みがすべて 0）では順番を変えないと、ユーザーが確かめている。
  使わない（ADR-0007 の確認は未了で、`slurm-run.sh` の `--top` は残っている）
- `scontrol hold` と `release` で並べ替えない。ほかのエージェントが、held のジョブを自分のものでないと誤解して取り消した
  ことがある
- 走っているジョブは止めない

## 複数のジョブを待つ

関係するジョブは、まとめて 1 つの background のコマンドで投げて待ち、途中の結果では報告しない:

```bash
~/.claude/scripts/slurm-run.sh -t 30 a '…' && ~/.claude/scripts/slurm-run.sh -t 30 b '…'   # 順に。a が失敗したら b は投げない
~/.claude/scripts/slurm-run.sh -t 30 a '…' & ~/.claude/scripts/slurm-run.sh -t 30 b '…' & wait   # 同時に投げ、待ち行列に任せる
```

後ろのジョブが前のジョブの出力を使うなら `&&`。独立なら `&` と `wait`（待ち行列が 1 本ずつ走らせる）。

## ログと時間

ログは r995 の `~/github/slurm-logs/<名前>-<ジョブ番号>.out`（`slurm-run.sh` が `LOG:` に出す）。終わった直後に、末尾へ
`TIME: elapsed=<実際> estimate=<見積もり>` が足される（ADR-0017）。全ジョブの履歴は `/var/log/slurm/job_completions`。

記録に書く時間は、排他のジョブの `elapsed` だけを使う。

## 排他でない投げ方（-c）

```bash
~/.claude/scripts/slurm-run.sh -c <コア数> -t <見積もり> <名前> '<コマンド>'
```

`--exclusive` を付けず、`<コア数>` の CPU だけを取る（ADR-0029）。時間を記録しない長い計算（何時間もの参照解、開発中の
試行）向け。

- コア数は Slurm の CPU（ハードウェアスレッド）で数える。OpenMC を 16 スレッドで走らせるなら `-c 16`（物理コア 8）
- ログの TIME 行の末尾に `shared (-c N): 時間は当てにならない` が付く。その時間を検証の記録に書かない
- 排他のジョブは、ノードにほかのジョブが走っている間は始まらない。排他でないジョブが走っている間は、あとから投げた
  排他のジョブ（時間を記録する測定を含む）が待つ。排他でないジョブどうしは重なる。排他の短いジョブとは重ならない
  （sbatch の `--exclusive` は、ほかのジョブとノードを共有しない）
- メモリは Slurm が数えない（`CR_Core`）。排他でないジョブを複数流すときは、メモリの合計が搭載量（RealMemory 86000 MB）を
  超えないよう自分で数える。超えると OOM killer が長い計算を殺す
- 名前の末尾に `-shared` を付ける（`openmc-2K-shared`）。jobcomp は排他かどうかを持たないので、付けないと
  `slurm-history.sh --by-name` の実績に、時間の当てにならないジョブが混ざる
- 連絡先に `shared-cpus=N` が付くので、`squeue` で待たされている理由が読める
- 時間を記録する測定の予定があるときは使わない

# Retro

同じ失敗が 2 回出たときと、ユーザーに訂正されたときに、ここまでの作業（$ARGUMENTS があればその範囲と観点）を振り返り、
同じ失敗や手戻りが次のセッションで起きないように、仕組み（hook、script、skill、prompt、memory）を直す。向きは種類で分ける。
文章（メモリ、スキル、CLAUDE.md）は毎回のセッションに読み込まれるので、減らす方向に直す。機械（hook、script）は毎回は
読み込まれないので、足してよい。

## 1. 手がかりを集める

会話の文脈に加えて、会話の記録をスクリプトで読む。文脈に無いサブエージェントの中の失敗と、要約より前の出来事、
同じ失敗の回数はここから取る:

```bash
~/.claude/skills/retro/scripts/session-events.sh
~/.claude/skills/retro/scripts/memory-index.sh <メモリのディレクトリ>
~/.claude/scripts/usage-report.py --repo <リポジトリ>...
```

- `session-events.sh`: `ERROR:` が区間の指定（`--since` / `--until` の形、前後）を指していれば、
  指定された区間のまま書き方を直して再実行する。区間に行が無いと出たら、年と時差の書き誤りを直すか、区間が
  `/clear` の前など別のセッションにあれば、その記録を TRANSCRIPT に渡して再実行する（区間をずらして合わせない。
  ほかの期間を数えることになる）。そのほかの `ERROR:` で止まったら、文脈だけで進め、報告にそう書く。
  振り返る区間を指定されたら（$ARGUMENTS の「11-06 00:00 から 11:05 まで」など）、
  `--since <日時> --until <日時>` を付けて区間の行だけを数える（付けないと記録の全体、長いセッションでは
  何日分もの回数になる）。出力の `SINCE:` / `UNTIL:` で、UTC に直した区間が意図どおりかを確かめる
- `memory-index.sh`: メモリのディレクトリは、このセッションの自動メモリの
  `MEMORY.md` があるディレクトリ（システムプロンプトに示される）。メモリが無いプロジェクトでは飛ばす。`ERROR:` で
  止まったら（辞書の検査が rebuild の前で無いなど）、出たほかの行で進め、`TERMS:` を見ていないことを報告の「未確認」に書く
- `usage-report.py`: トークン効率の
  方針の効きを振り返りごとに比べるため、`PER_MERGE:`（マージ 1 本あたりの費用）と `REWRITES:`（文脈の書き直し。
  1 回の応答で 25 万トークンを超える書き込み）を報告の「費用」に書く。区間は
  `session-events.sh` と同じ `--since` / `--until` を付け、区間の指定が無ければ省く（JST の今日になる）。`--repo` には
  区間にマージしたリポジトリをすべて渡す（このセッションの作業ディレクトリのリポジトリと、`~/.claude` の生成元など）。
  GitHub のリモートがあるリポジトリは `origin/HEAD` のマージを数えるので、先に `git -C <リポジトリ> fetch` する。
  `ERROR:` が価格表に無いモデルを指せば、スクリプトの `PRICES` に価格のページの値を足す PR を出し、報告の
  「費用」は「未確認」にする。ほかの `ERROR:` も同じく「費用」を「未確認」にして進める

これと会話の文脈から、次の手がかりを拾う:

| 手がかり                                                               | 疑うこと                                                             |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 撤去したもの、置き換えたもの                                           | それを指す hook、skill、CLAUDE.md、メモリが残っている                |
| hook にしたルール                                                      | CLAUDE.md や skill の同じ記述が不要になった                          |
| 2 つの文書が同じ手順を別々に書いている                                 | 片方だけが直って古いまま残っている                                   |
| 理由がもう当てはまらない注意、skill や hook と重なるメモリの句         | 消してよいのに残っている                                             |
| 手作業で補った決定的な処理（数える、比べる、探す、ハッシュの更新など） | スクリプトが無い、あるのに手順から呼ばれていない                     |
| 同じ hook の拒否が 2 回以上                                            | 拒否の文言が修正方法を示していない、スキルの手順が hook と食い違う   |
| 同じ種類のツールの失敗、やり直し                                       | 手順の不備（古い前提、抜けた確認）、スクリプトにすべき手作業         |
| 外部ツールの無駄な出力、読み飛ばした警告                               | 出力を絞るか、意図された警告か                                       |
| ユーザーの訂正                                                         | 手順や指針の誤り（skill、CLAUDE.md）、またはまだ記録されていない好み |
| ユーザーが示した好み、環境の事情                                       | メモリに無い、または既存のメモリと食い違う                           |

## 2. 裏取りする

候補ごとに、根拠を実際のファイルで確かめる。読むのは、対象のスクリプト、hook のルールとテスト、スキル、CLAUDE.md、
ADR、既存のメモリ、git の履歴。

- 今の形に理由が書かれていれば（設計のコメント、ADR の検討した案）、その理由が今も成り立つかを見る。成り立てば
  候補から外し、「見送り」に理由とともに残す
- 既存のメモリ、ADR、issue に同じ話があれば、新しく作らずにそれを更新する案にする
- ほかのブランチ、worktree、開いている PR が同じものを直していないかを見る（`git worktree list`、`gh pr list`）。
  直していれば、その PR に任せる
- 確かめられなかったことは「未確認」と書いて残す

## 3. 置き場所を決める

| 置き場所                 | 置くもの                                                                                                  |
| ------------------------ | --------------------------------------------------------------------------------------------------------- |
| hook                     | コマンドの文字列や git・GitHub の状態から機械的に判定できる禁止と必須。拒否の文言には理由と修正方法を書く |
| script                   | 入力が決まれば結果が 1 つに決まる手順（数える、比べる、探す、決まった順序）                               |
| skill                    | 判断が要る手順。そのスキルだけを読めば使える形にする                                                      |
| グローバルの CLAUDE.md   | 判断の指針と、自力で気づけない罠だけを 1 行で。hook が強制することは hook の文言に任せる                  |
| プロジェクトの CLAUDE.md | そのリポジトリだけの規則                                                                                  |
| 依頼の定型（prompt）     | サブエージェントや別のセッションへの頼み方。頼む側の書き方を持つスキルに置く                              |
| memory                   | ユーザーの好みと、コードと git の履歴から読み取れない事情だけ。「次は気をつける」の類の注意は置かない     |
| ADR                      | 案を比べて選んだ決定                                                                                      |
| issue                    | 今は直さない問題                                                                                          |

- 同じ問題に複数の置き場所が効くときは、強い方（hook > script > skill > CLAUDE.md）に置き、弱い方の重なる記述は消す
- 同じ失敗が 2 回出たら、hook か script にできるかを先に見る。できなければ既存の 1 文を直し、新しい文を足さない
- 禁止を足したくなったら、守る中身の置き場所と運用を肯定形で書く
- 仕組みを新しく作るときは、一般的なツールや作法での解き方を先に調べ、それを基本にする
- `~/.claude` の CLAUDE.md、skills、scripts、hook は生成物で、生成元のリポジトリ（`claude-sync` の既定は
  `~/nix/nixfiles`）で直す。メモリはそのディレクトリで直す

## 4. 進め方を決める

効果の大きい順に並べる（同じ失敗の回数、失敗が起きたときの手戻りの大きさ、黙って誤る危険）。

確認せずに進めるもの:

- 文章（メモリ、スキル、CLAUDE.md）を消す、縮める（メモリは `git -C ~/.claude` の refs/memory-backup から戻せる。スキルと
  CLAUDE.md は PR とそのレビューを通る）
- メモリの追加、更新、統合と、`memory-index.sh` が出した `MISSING:`、`UNINDEXED:`、`BROKEN_LINK:`、`TERMS:` の修正（直接書く）
- 1 つのトピックで閉じる、hook・script・skill・プロジェクトの CLAUDE.md の修正と追加（PR とそのレビューを通す）

先にユーザーに見せて指示を受けるもの（優先度つきの一覧で、1 案ずつ推しを添える）:

- hook のルール、スクリプトを消す、またはゲートを緩める
- グローバルの CLAUDE.md に足す、または意味を変える
- 採用中の ADR と違う方向にする（新しい ADR が要る）
- 他人のプロジェクトや外部への公開を伴う
- 1 つのトピックに収まらない、または置き場所の候補が 2 つ以上残って推奨を 1 つに決められない（推奨を持てるものは、推奨で
  進めて報告する）

## 5. 実行する

- メモリは直接書く。足すより先に、既存の項目を直すか消し、索引（`MEMORY.md`）の 1 行も合わせて直す
- それ以外は、1 トピック 1 ブランチ 1 PR にする。トピックの切り方は /topic-triage の「振り分け」に従い、作業は
  /delegate の頼む側の形でサブエージェントに渡すか、自分で worktree を作って進める。同じファイルを触るトピックは
  並べずに順に進める
- 今は直さないものは issue に書く（GitHub のリモートがあれば `gh issue create`、なければ `docs/issues/`）

## 6. 報告する

報告の前に、文章の増減を数える。区間は `usage-report.py` と同じにし、`--repo` には 5. のブランチの worktree も渡す:

```bash
~/.claude/skills/retro/scripts/prose-size.sh --since <日時> --memory <メモリのディレクトリ> --repo <パス>...
```

```markdown
## 改善

| # | 種類 | 変更 | 根拠（確かめた事実） | 置き場所 | 状態 |
| - | ---- | ---- | -------------------- | -------- | ---- |
| 1 | hook / script / skill / prompt / memory | 削除 / 修正 / 追加 | <ファイルと行、回数、ユーザーの発言> | <パス> | 実行済み / PR <URL> / issue <URL> / 提案のみ |

## 文章の増減

<`PROSE:` の行ごとに種類、前、後、差。増えた行には理由を 1 文。`ERROR:` で数えられなかったものは「未確認」に>

## 費用

| 区間 | 合計 | 親 | 担当 | レビュー | 振り返り | マージ 1 本あたりの費用 | 文脈の書き直しの回数 |
| ---- | ---- | -- | ---- | -------- | -------- | ----------------------- | -------------------- |
| <`SINCE:`〜`UNTIL:`> | <`TOTAL:`> | <`COST:` の費用と割合> | 〃 | 〃 | 〃 | <`PER_MERGE:`> | <`REWRITES:` の回数と費用> |

## 指示が欲しいもの
<4. の確認するものを、優先度の順に。各項目に推す案を 1 つ>

## 見送り
- <候補> — <理由（設計の意図、既存の PR が対応中など）>

## 未確認
- <確かめられなかった前提>
```

該当の無い節は「なし」と書く。

# ADR-0047: 依存の基準に、事実上の標準のライブラリとツールを含める

## 背景

グローバルの CLAUDE.md の設計指針は「標準ライブラリで実現できるなら外部依存を追加しない」だった。標準ライブラリの
狭い言語では、広く使われて保守も安定したライブラリまで避ける意味に読まれる。xlc の計画は、スレッドの並列化を標準ライブラリ（Rust の
`std::thread::scope`）で書くとしていたのを、ユーザーの指摘で事実上の標準のライブラリ（rayon）に替えた（xlc の 131e8b79、2026-10-06）。

ユーザーの言葉（2026-10-21）: 「標準ライブラリが狭すぎるので、Global の標準の意味が狭くなっているだけです」「Global な
CLAUDE.md に（特定の言語）特有の例示を上げるのはやめてくださいね」。基準の目的は、保守コストを増やさないことである。

## 検討した案

- 案 A: 標準ライブラリを先に、足りないときだけ事実上の標準を使う、と順序を書く。標準ライブラリの上の手書きで足りれば、
  事実上の標準のライブラリがあってもそちらを選ぶことになり、手書きのコードの保守コストを数えない。ユーザーの「実質標準」と食い違う
- 案 B: 言語ごとの例（ライブラリの名前）を挙げる。PC 全体で読み込むファイルに特定の言語を持ち込む（ユーザーが退けた）
- 案 C: 標準ライブラリと、言語やエコシステムで事実上の標準のライブラリとツールを同じ側に数え、手書きと比べて保守コストの
  小さい方を選ぶと肯定形で書く。それ以外の依存は、これらで実現できないときだけ足す

## 決定と理由

案 C。ADR-0044 に従い、することを先に書く。対象にツールを含めるのは、ADR-0014 が textlint と prh を「事実上の標準で
nixpkgs にある」として選んだように、依存はライブラリに限らないため。

## 帰結

- 依存は、事実上の標準でも保守コストに数える。ADR-0012 のように手書きが小さく済むものは、依存を足さない判断が残る
- 何が事実上の標準かは、言語ごとに違うのでこの文書では定めない。迷う依存は、出典（採用の広さ、保守の状況、nixpkgs に
  あるか）を添えて比べ、ユーザーに決めてもらう

## 確認

- 新しい依存を足す PR は、その依存が事実上の標準か、手書きと比べて保守コストが小さいかを本文に書く。レビューはそれを見る

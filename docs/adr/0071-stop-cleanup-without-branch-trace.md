# ADR-0071: post-merge-cleanup.sh はブランチの痕跡が無ければ何もせずに止まる

## 背景

`post-merge-cleanup.sh <branch>` は cwd のリポジトリで、worktree の削除、既定ブランチの最新化、予約のタグの解放
（ADR-0018）、ローカルとリモートのブランチの削除を行う。未マージの確認（0）はローカルのブランチがあるときだけ行い、
1、4、5 はブランチが無ければ `none` を出して飛ばす。どこにもブランチが無くても、`none` を並べて 0 で終わる。

2026-11-03 に、xlc のセッションが nixfiles の PR をマージした後、cwd が xlc のまま
`post-merge-cleanup.sh docs/delegate-cite-record-values`（nixfiles のブランチ）を実行し、`WORKTREE_REMOVED: none`、
`RESERVATIONS_RELEASED: none`、`LOCAL_BRANCH: none`、`REMOTE_BRANCH: none` を出して 0 で終わった。nixfiles の
worktree とブランチは残り、xlc の既定ブランチの pull と予約のタグの prune が走った。nixfiles の中でやり直して片付いた
（xlc の親のセッションの記録、2026-11-03T03:38:42Z と 03:39:05Z のツールの結果）。

一方で、ブランチの一部が既に消えた後の呼び出しは正当である。`gh pr merge --delete-branch`（gh 2.103.3 の
`pkg/cmd/pr/merge/merge.go` の `deleteLocalBranch` と `deleteRemoteBranch`）は、ブランチが今の worktree に
チェックアウトされていなければ、ほかの linked worktree を `git worktree remove` で消し、ローカルのブランチを
`git branch -D` で消し、リモートのブランチを API で消す。手元のリモート追跡の ref（`refs/remotes/<remote>/<branch>`）には
触れない（`git/client.go` の `DeleteLocalBranch` は `git branch -D` だけ）。その後の post-merge-cleanup.sh には、
既定ブランチの最新化と予約のタグの解放が要る。リモート追跡の ref も、別のセッションの post-merge-cleanup.sh の
`git fetch --prune`（2）が先に走れば消える。並行して複数のセッションが同じリポジトリでマージするので、起こりうる。

## 決定の要因

- 別のリポジトリで呼んだことに、呼ぶ側が気づける（黙った成功を作らない）
- 別のリポジトリでは何も変えない（既定ブランチの pull や予約のタグの prune も、そのリポジトリには要らない）
- gh がブランチを消した後と、途中で失敗した片付けのやり直しを止めない

## 検討した案

痕跡が無いときの扱い:

- 案 A（採用）: 何もせずに ERROR（終了コード 1）で止まる。拒否の文言に調べたリポジトリのパスと修正方法を書く
- 案 B: 既定ブランチの最新化と予約のタグの解放は続け、終了コードを 0 以外にする。別のリポジトリで呼んだときに、
  そのリポジトリの pull と prune が走る（どちらも、そのリポジトリのマージに無関係）。終了コードが 0 でないのに
  変更が入り、呼ぶ側はどこまで進んだかを出力から読む必要がある
- 案 C: `WARN:` を出して 0 で終わる。今と同じく、終了コードで判定する呼ぶ側（スキルの手順）は気づかない

痕跡に数えるもの:

- 案 D（採用）: ローカルのブランチ（チェックアウトした worktree はローカルのブランチを持つので、これで数える）、
  リモートごとのリモート追跡の ref、ブランチの remote（無ければ origin）の `git ls-remote --heads`、GitHub リモートでは
  そのブランチを head とするマージ済みの PR（`gh pr list --head <branch> --state merged`）
- 案 E: 案 D から GitHub のマージ済みの PR を除く。gh が消した後にリモート追跡の ref が `fetch --prune` で先に消えると、
  正当な呼び出しを止め、予約のタグが解放されない
- 案 F: 案 D に、既定ブランチの履歴のマージコミットの本文の `Branch: <branch>` の行（/git-merge の本文の末尾の行）を足す。
  痕跡が全部消えた後に /git-merge のリポジトリで呼ぶのは、片付けを終えた後の再実行だけで、残る作業が無い（最新化する
  リモートが無く、予約のタグは前の実行が解放した）。止めても失うものが無く、文言で済んだ後なら何もしなくてよいと示せば足りる。
  /gh-pr-merge の本文（`PR: #<番号>`）はブランチ名を含まないので、GitHub の側の証にもならない

呼ぶ側の入力:

- 案 G: 呼ぶ側がリポジトリを渡す（/gh-pr-merge は PR の URL、/git-merge はリポジトリのパス）。スクリプトは cwd のリモートと
  照らし、ブランチ名の重なりに頼らずに別のリポジトリを見分けられる。2 つのスキルの呼び出しの形を変える。ローカルの
  レビューで挙がった案で、このブランチでは採らず #559 に残した

`git ls-remote` が失敗したとき（リモートに届かない）と、gh が無いか `gh pr list` が失敗したときは、痕跡の有無を確かめられない
ので、理由を添えて止める（何も変えていないので、原因を直してやり直せる）。

## 決定と理由

案 A と D にする。確かめるのは 0（未マージの確認）の前で、ネットワークに行くのは手元（ローカルのブランチとリモート追跡の
ref）に痕跡が無いときだけである。手元に痕跡があれば今までと同じに動く。

止める文言は、調べたリポジトリ（メインの worktree のパス）と、修正方法（そのブランチのリポジトリの中で実行する。別の
リポジトリのブランチなら `cd <そのリポジトリ> &&` を付ける）と、片付けが済んだ後の再実行なら何もしなくてよいことを書く。

GitHub のマージ済みの PR はブランチ名だけで照らすので、別のリポジトリのブランチと同じ名前の古い PR でも通る（2026-11-03 に、
xlc の既定ブランチのマージの本文の `Branch:` 440 本と、nixfiles のマージ済みの PR の head 407 本のうち、
`docs/adr-amends-links` と `docs/slurm-job-names` が重なった）。手元から見分ける手がかりが無いので、マージ済みの PR だけが痕跡の
ときは、その PR の URL を `NOTE:` の行で出し、呼ぶ側が自分の PR かを読めるようにする（gh pr list は新しい順に返すので、
最も新しい PR）。

リモートの無いリポジトリ（/git-merge の後）で片付けを全部終えた後にもう一度呼ぶと、痕跡が無いので止まる。最新化する
リモートが無く、予約のタグは前の実行が解放したので、やり直しは要らない。

### 帰結

- 別のリポジトリのブランチ名、打ち間違えたブランチ名、片付けを終えた後の（GitHub 以外での）再実行は、終了コード 1 で止まる
- GitHub リモートで、手元にもリモートにも痕跡が無いときだけ、`gh pr list` を 1 回呼ぶ
- 出力の行の形（`WORKTREE_REMOVED:` など）は変えない。止まるときは標準エラーに `ERROR:` と `修正方法:` の行を出す。
  マージ済みの PR だけが痕跡のときは、標準出力の始めに `NOTE:` の行を足す
- 名前の重なる古い PR のある GitHub のリポジトリでは、別のリポジトリのブランチ名でも止まらない（NOTE で知らせるだけ）。
  呼ぶ側がリポジトリを渡す形（案 G）は #559

### 確認

- `.claude/tests/scripts/git-workflow.sh` の post-merge-cleanup のテスト: 痕跡の無いブランチ名で、worktree、既定ブランチ、
  予約のタグを変えずに止まり、リポジトリのパスと `cd <そのリポジトリ> &&` を示す。リモートの無いリポジトリでも止まる。
  gh が消した後（リモート追跡の ref だけ残る）、リモートのブランチだけ残る、GitHub でマージ済みの PR だけがある（その PR の URL を
  NOTE で出す）、のそれぞれで片付けを続ける。GitHub でマージ済みの PR も無い、`gh pr list` が失敗する、リモートに届かない、のそれぞれで止まる

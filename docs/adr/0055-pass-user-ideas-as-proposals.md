# ADR-0055: ユーザーの案は親の評価を添えて「案（決定ではない）」として渡し、受ける側も評価する

## 背景

2026-10-23 に、親がユーザーの案（ライブラリの作成で、1 CPU ずつ重い順に 16 本を投入する）を、自分の評価を書かずに
担当へ渡した。ユーザーの言葉: 「私の案はあくまで案であり技術的に筋が悪かったら拒否・改善提案をするように伝えているよね？」。
依頼のテンプレート（ADR-0044 の 3 つの欄）のうち、delegate のスキルは「何をするか」を決定済みの内容と判断の軸を書く欄と
説明しているので、案を書くと決定として読まれる。

## 検討した案

- 案 A: 頼む側は、ユーザーの案に親の評価（賛否と理由、成り立つ条件、反例を探した範囲。測らないと決められなければ
  その旨と、測る回数の上限を「完成の形」に）を添え、「何をするか」の中で「案（決定ではない）」と明示する。成り立たないか、
  より良い代案があると親が判断した案は、理由と代案をユーザーに返し、依頼には入れない。受ける側は作る前から
  チェックとレビューの間まで評価して報告に書き（案に含まれる出典で確かめられる前提は ADR-0054 の規則で確かめる）、
  成り立たなければ（反例がある）その時点で止まって報告する。成り立つがより良い代案があるときは、案のとおり作って代案を報告に書く（止まる基準を「より良い代案」に
  すると、わずかな好みの差で依頼が止まりうる）
- 案 B: テンプレートに「案」の欄を足す。ADR-0044 の 3 つの欄を変えることになり、案は「何をするか」の一部なので採らない
- 案 C: 印の無い「案」の語で決定でないとみなす。ADR の「案 A に従う」と書いた依頼まで再検討の対象になる
- 案 D: 成り立たない案の項目だけを外し、ほかの項目は進める。外した項目が完成の形に入っていると報告の扱いが決まらず、
  親が欠けに気づかずにマージしうる

レビューで作り直す前の案 A の版と、捨てた理由:

- 案が成り立たないときに、作った分をコミットして `git status` を空にしてから止まる: 手順 6 の「途中で止まるときは残った
  変更を報告に書く」と食い違い、hook がコミットを拒んだときの扱いが無かった。既存の途中で止まるときの扱いに任せた
- 案が成り立たないときだけチェックとレビューを飛ばす: 報告の前の片付け（手順 9）と報告の形（確認の結果）の両方と
  食い違った。止まり方は既存の扱いに任せ、案に固有のことは理由、反例、代案の置き場だけにした
- 親の評価に「確かめた反例」を添える: 反例が確かめられた案は成り立たない案なので依頼に入れないと決めており、矛盾した。
  「反例を探した範囲」にした
- 案の「前提が誤り」でも止まる: 出典で確かめられる前提は ADR-0054 の規則が作業の前に確かめると決めており、止まる時点が
  2 通りになった。前提の確認は ADR-0054 に任せ、止まる条件は反例だけにした
- 評価の時点を「作る前と作る途中」、止まる手順を 4〜7 に限る: チェックとレビューで成り立たないと分かる場合と、手順 1 で
  反例を見つけた場合の扱いが無かった。評価はチェックとレビューの間まで続け、どの手順でもその時点で止まる

## 決定と理由

採用: 「案 A」。ADR-0044 の 3 つの欄は変えず、「何をするか」の中で案を決定と区別して渡し、両側で評価する。止まったときは、ほかの途中で止まるときと同じく報告し、止まった理由を
「親が先に読む要点」に、反例と代案を「マージの前後で人の手が要ること」に書く（代案は親とユーザーが決めることで、
担当が決めたことではない）。

### 帰結

- 筋の悪い案が 1 つあると、依頼の全体が止まり、往復が 1 回増える

### 確認

- `.claude/skills/delegate/SKILL.md` の受ける側の手順 1 と、頼む側の書き方とテンプレートに、「案（決定ではない）」の扱いがある

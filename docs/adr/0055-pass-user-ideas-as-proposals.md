# ADR-0055: ユーザーの案は親の評価を添えて「案（決定ではない）」として渡し、受ける側も評価する

## 背景

2026-10-23 に、親がユーザーの案（ライブラリの作成で、1 CPU ずつ重い順に 16 本を投入する）を、自分の評価を書かずに
担当へ渡した。ユーザーの言葉: 「私の案はあくまで案であり技術的に筋が悪かったら拒否・改善提案をするように伝えているよね？」。
依頼のテンプレート（ADR-0044）の「何をするか」は決定済みの内容を書く欄で、案を書くと決定として読まれる。

## 検討した案

- 案 A: 頼む側は、ユーザーの案に賛成の理由（成り立つ条件、確かめた反例）を添え、「何をするか」の中で
  「案（決定ではない）」と明示する。親が筋が悪いと判断した案は、理由と代案をユーザーに返し、依頼には入れない。
  受ける側は作る前と作る途中に評価し、筋が悪ければ、依頼と ADR が食い違うときと同じく止まって報告する
- 案 B: テンプレートに「案」の欄を足す。ADR-0044 の 3 つの欄を変えることになり、案は「何をするか」の一部なので採らない
- 案 C: 印の無い「案」の語で決定でないとみなす。ADR の「案 A に従う」と書いた依頼まで再検討の対象になる
- 案 D: 筋の悪い案の項目だけを外し、ほかの項目は進める。外した項目が完成の形に入っていると報告の扱いが決まらず、
  親が欠けに気づかずにマージしうる

## 決定と理由

採用: 「案 A」。案を決定と区別して渡し、両側で評価する。止まったときは、止まった理由を「親が先に読む要点」に、代案を
「マージの前後で人の手が要ること」に書く（代案は親とユーザーが決めることで、担当が決めたことではない）。

### 帰結

- 筋の悪い案が 1 つあると、依頼の全体が止まり、往復が 1 回増える

### 確認

- `.claude/skills/delegate/SKILL.md` の受ける側の手順 1 と、頼む側の書き方とテンプレートに、「案（決定ではない）」の扱いがある

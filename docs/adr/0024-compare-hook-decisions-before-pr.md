# ADR-0024: claude-hooks の読み方やルールを書き直したら、PR の前に古い版と判定を比べる

## 背景

PR #301（#296）で、規則ごとに書いていたコマンドの読み方（包みのほどき方、git のオプションの読み方）を
`shell.rs`、`unwrap.rs`、`git_args.rs` にまとめた。`.claude/tests/hooks.sh` は書いた形しか見ないので、
書き直しで main より緩くなった形（`env -- CLAUDECODE=0 git commit`、`env cd <dir>; git commit`、
`git add -A --pathspec-from-file=…`）は、テストが全て通ったまま残った。前の 2 つは main とこのブランチの
バイナリに同じコマンドの集まりを流して比べて見つけ、最後の 1 つは比べる形に入っておらず、Copilot の
レビューで見つかった。

## 検討した案

- 案 A: hooks.sh のテストを増やすだけにする。書き直しのたびに、どの形が変わりうるかを書く人が予想する
  ことになり、予想しなかった形を見逃す（上の 2 つ）
- 案 B: その場限りのスクリプトで比べる。#301 ではそうしたが、比べる形が回ごとに違い、`--pathspec-from-file`
  を見逃した
- 案 C（採用）: 比べる道具（`.claude/tests/hooks-diff.sh`）を置き、包み・ディレクトリの移り方・コマンドの
  組み合わせを固定して、ルールごとに比べる
- 案 D: claude-hooks の出力に、止めたルールの名前を入れ、版ごとに 1 回の呼び出しでルールごとの差を出す。
  呼ぶ回数は 1/ルール数に減るが、hook の出力の形（Claude Code に渡す JSON）を、道具のために変える。
  案 C で 1 回の比較が 1.5 分なので、今は要らない

## 決定と理由

案 C を採る。claude-hooks のコマンドの読み方かルールを書き直したら、PR の前に
`bash .claude/tests/hooks-diff.sh [BASE]` を走らせ、`LOOSENED`（古い版が止め、新しい版が通す）の行を、
意図した変更か後退かで 1 つずつ見分け、件数と理由を PR の Tests に書く。

判定はルールごとに比べる。比べる場所の main（GitHub のリモートあり）では block-main-commit が全ての
コミットを止めるので、ルールをまとめた判定で比べると、他のルールの緩みが隠れる。#301 の前の main
（1fe29ef^1）と後の版を比べると、まとめた判定が変わったときだけルールごとに比べた最初の版では
`LOOSENED` が 72 件、ルールごとに比べると 141 件だった（2026-10-11、feat/hooks-diff の 4ae2ccf）。

### 帰結

- 書き直しの PR では、1 回 1.5 分ほどの比較が増える（1,656 個のコマンド × 15 ルール × 2 版）。1 コアの処理で、
  計算資源を争わないので、Slurm には流さない
- 比べる形は道具の中の表で決まる。表に無い形は、案 A と同じく見逃す。見逃した形が見つかったら表に足す。
  古い版が一度も通す以外を返さないルールは `UNCOVERED` に出る（緩んでも見えない）

### 確認

- `.claude/tests/scripts/hooks-diff.sh` が、偽のバイナリで、緩み・厳しくなったもの・隠れた緩み・
  無くなったルール・deny 以外の変化・バイナリの失敗を確かめる

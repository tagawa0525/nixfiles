# ADR-0054: 依頼に書くリポジトリの事実も出典で確かめる

## 背景

ADR-0027 の補足（2026-10-22）は、依頼に書く外部の値（ツールの既定値、仕様の数値）を、頼む側も受ける側も出典で
確かめると決めた。対象のリポジトリの事実（何を出力し何を残すか、入力の中身）は対象の外だった。

2026-10-23 に xlc の燃焼の作業で、親が依頼に「燃焼の履歴は k・数密度・ピン出力しか残さない」と書いた。実際には
入力の項目（`[depletion]` の `few-group`）で少数群定数を残せた。担当はこの前提を土台に設計した。同じ日に、仕様の
2 つのケースの吸収体と表の番号も取り違えて依頼に書いた。

## 検討した案

- 案 A: 外部の値の規則を、リポジトリの事実と仕様の表の番号、体系の構成に広げ、1 つの規則にする。受ける側は頼む側の
  一覧を参照する
- 案 B: リポジトリの事実の規則を別に足す。ローカルレビューで、確かめられないときの扱い（「確かめていない」と書く）が
  片方から抜け、受ける側と頼む側の一覧もずれた
- 案 C: 受ける側の「コードの事実と食い違えば止まる」に任せる。2026-10-23 の誤りはこれで止まらなかった（「残さない」は
  書き出す箇所を読んでも食い違いが見えず、切り替える入力の項目を読んで初めて分かる）

## 決定と理由

採用: 「案 A」。

- 頼む側は、依頼に書く値と前提を出典で確かめ、出典を添える。外部の値は版と、ファイルの行か文書のページや節。
  リポジトリの事実は、ファイルと関数名（行は main が進むとずれる）。出力について書くときは、書き出す箇所だけでなく、
  それを切り替える入力の項目と設定も読む。確かめていないものは「確かめていない」と書く
- 受ける側は、頼む側の一覧にある種類の値と前提を、作業の前に出典で確かめる

案 B は二重の記述がずれる。案 C は、否定の事実や入力で切り替わる出力を拾えない。

### 帰結

- ADR-0027 の補足（2026-10-22）の「外部の値」の規則は、この ADR が広げる
- 依頼を書く手間は、出典を 1 度読む分だけ増える

### 確認

- `.claude/skills/delegate/SKILL.md` の「頼む側」の出典の規則がリポジトリの事実を含み、受ける側の手順 1 がそれを参照する

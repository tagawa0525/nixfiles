# ADR-0005: ADR の形はスキルで示し、hook で読み込みと節を確かめる

## 背景

ADR の形はどこにも書かれておらず、既存の ADR を手本に書いていた。手本を真似ると、欠陥も一緒に複製される。
2026-10-10 には、ADR-0002 に書いたホストの状態の項目と再開手順の節を、ADR-0003 が同じ形で真似た。
周りに合わせて書くのはモデルの既定の振る舞いなので、モデル自身は誤りに気づきにくい。

- 規則を増やすより、一般的な知識（MADR）を基準にする
- 他人のプロジェクトにはその流儀があり、こちらの形を押し付けない

## 検討した案

- 案 A: CLAUDE.md に 1 行足す。常に読まれるが、形の中身までは持てない
- 案 B: スキルだけにする。形を持てるが、呼ばずに書くと効かない
- 案 C（採用）: スキルと hook。スキルが形と書かないものを持ち、hook が書き込みの前にスキルの読み込みを、
  コミット時に節を確かめる
- hook で中身（決定か状態か）を判定する案は採らない。意味の判断なので機械的にはできず、レビューに任せる
- 他人のプロジェクトの見分け方:
  - 既定で無効にし、自分のリポジトリで有効にする。clone のたびに設定が要る
  - origin の所有者だけで決める。fork を自分のものと誤る

## 決定と理由

案 C にする（ユーザーの判断）。

- **スキル `adr`**: 形は MADR に倣う（背景・検討した案・決定と理由・帰結・確認）。書かないもの（状態、未解決の
  作業、コードの写し、手順書）と、その置き場所を示す
- **`require-adr-skill`**: Skill ツールの呼び出しを hook 自身がセッション単位で記録し、`docs/adr/` への書き込みの
  前に確かめる。モデルが付ける印ではないので、読まずに通ることはできない
- **`check-adr-sections`**: 節を 5 つに限り、背景と決定と理由を必須にする
- **他人のプロジェクトでは外す**: 既定は有効。`upstream` を持つ fork か、GitHub のリモートの所有者に自分
  （`claude-hooks.owner`）以外がいれば他人のプロジェクトと判定し、`git config claude-hooks.own-project` に
  書く。手で書いた値を優先する

## 帰結

- 節が形に合わない既存の ADR（ADR-0001 の「結果」、ADR-0002・0003 の「再開するとき」）は、変えるときに直す
- hook の対象が Bash 以外のツールに広がり、Write / Edit のたびに hook が 1 回走る
- 他人のプロジェクトの判定が、git の hook の fork 判定（`upstream` の有無）と別にある。寄せるかは #266 で扱う
- hook で確かめられるのは読み込みと節まで。中身はレビューに頼る

## 確認

- `.claude/tests/hooks.sh` に `require-adr-skill` と `check-adr-sections` のテストを足した

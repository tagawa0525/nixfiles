# ADR-0081: ユーザーの発言は括らず、場面と意図の要約で書く

## 背景

ADR-0065 は、依頼でユーザーの言葉を「」で括って引用するときは会話の記録（`.jsonl`）からそのままコピーしてパスと
`timestamp` を添え、受ける側が `.claude/scripts/quote-in-transcript.sh` で記録の発言に同じ文があるかと、引用の両端が文の
区切りか「…」に当たるかを確かめる、と決めた。ADR や issue に書く形は `「<引用>」（ユーザー <日付>）` と、括らない
`<要約>（ユーザー <日付>）` の 2 つだった。ユーザーの言葉は決定の出典で、事実の出典ではない（ADR-0060）。ユーザーの案は
「案（決定ではない）」として渡す（ADR-0055）。

2026-11-11 に、xlc の親がスキルの指示の見直しの結果を報告した場面で、ユーザーは、自分の発言を文脈から外して原文のまま
書くのをやめ、意図を読み取って適切な表現に書き換えるよう求めた。その文脈で見ないと伝わらず、原文のままでは誤解される
可能性の方が高い、という理由（ユーザー 2026-11-11。記録
/home/tagawa/.claude/projects/-home-tagawa-github-xlc/19a8117a-5afe-4e17-adf9-13d6bed755c6.jsonl の 2026-11-10T16:37:49.947Z。
nixfiles の #667 の「追加の提案: ユーザーの言葉は、原文のコピーでなく意図で書く形を基本にする」）。nixfiles の親がこの提案を
妥当と判断して、既にある引用を履歴ごと書き換えるか今のファイルを直すかを尋ね、ユーザーは、個人のリポジトリなので履歴ごと
書き換えてもよいが、今のファイルを直すだけのブランチでもよいと答えた（ユーザー 2026-11-11。記録
/home/tagawa/.claude/projects/-home-tagawa-nix-nixfiles/8f82315a-dead-4565-89f2-f432fdc2d18a.jsonl の 2026-11-10T18:19:39.753Z）。
親は今のファイルを直す方を選んだ。凍結する部分の中の引用も要約に直すことは、この答えをもとに親が決めた。

2026-11-11 の main（d8bfa55b）では、docs/adr に `「<引用>」（ユーザー <日付>）` の形の括った引用が 30 か所（行をまたぐものを含む）、
`ユーザーの言葉（<日付>）: 「…」` や `ユーザーが「…」と決めた` の形の引用がほかに約 17 か所あった。
`quote-in-transcript.sh` を呼ぶのは delegate の受ける側と頼む側の文、そのテスト、`.claude/README.md` の表、/delegate の
allowed-tools と modules/home/parts/claude-code.nix の許可リストだった（hook からは呼ばれない）。

## 検討した案

- 案 A（ADR-0065 の決定を続ける）: 括った原文を記録で確かめて ADR に残す。原文が確かに残り、親の言い換えを括る誤りは
  script が見つける。ただ、発言を前後のやり取りから外して置くので、読む側が意味を取り違えうる（ユーザーが退けた理由）。
  頼む側は引用のたびに記録からコピーし、`timestamp` を引く手間がかかる
- 案 B: 括らず、どの場面で何を求めたかを要約で書く。出どころを示すときは、記録のパスと時刻を添える。ADR-0065 の検討した
  案 B（判断の要約と日付で渡す）に、場面を書くことと、記録を指すことを足した形。ADR-0065 が案 B を退けた理由（ユーザーの
  原文が委任した ADR に入らなくなる損）は、原文だけを置く方が誤解されやすいというユーザーの判断で、損に当たらなくなった
- 案 C: 括った引用を残し、前後の場面を書き添える。原文と場面の両方が残るが、文が長くなり、括った原文が決定の根拠として
  文脈から切り出されて読まれる点は残る
- `quote-in-transcript.sh` の扱い: (1) 残す、(2) 記録のパスと時刻から発言とその前後を出す形に作り替える、(3) 消す。
  (1) は引用の一致を確かめる役目が無くなり、呼ぶものが無い。(2) は今の script が文で発言を探す形なので作り直しになり、
  時刻で前後を読む用途は `jq` か Read で記録を開けば足りる

## 決定と理由

案 B と、script は (3)。ユーザーの判断（背景）のとおり、発言は場面と意図で書く。括らなければ、親の言い換えを原文として
括る誤り（ADR-0065 の背景）は起きない。script は必要になるまで作らない。

- 頼む側: ユーザーの言葉（判断、承認、案）は「」で括らず、どの場面で何を求めたかを `<要約>（ユーザー <日付> の発言の要約）` と
  書く（日付は JST）。出どころを示すときは、会話の記録の `.jsonl` のパスと、その発言の `timestamp`（UTC のまま）を添える。
  記録は `~/.claude/projects/` の下の、会話を始めたディレクトリ（worktree を含む）ごとのディレクトリにある（ファイル名の ID は
  `Claude-Session:` の ID と別）
- 受ける側: ADR や issue に書くユーザーの言葉は括らず、`<要約>（ユーザー <日付>）` と書く。日付は JST（記録の `timestamp` は
  UTC）で、分からなければ「日付不明」と書く
- delegate の受ける側は、ユーザーの判断と承認を、依頼と追加の指示がユーザーの言葉として書いたときだけ書く（依頼そのものは
  承認ではない。ADR-0065 から引き継ぐ）
- `.claude/scripts/quote-in-transcript.sh` とそのテストを消し、/delegate の allowed-tools と claude-code.nix の許可リストから
  外す

### 帰結

- 委任で書いた ADR と issue には、ユーザーの判断が場面と意図の要約で入り、原文は入らない。原文を読みたいときは、添えた
  記録のパスと時刻から前後のやり取りごと読む（Claude Code は古い記録を消すので、消えた後は要約だけが残る）
- 頼む側が記録から原文をコピーし、`timestamp` を引く手間は無い
- 要約の誤り（引用に無い意図を足す、条件を落とす）は、機械では見つからない。頼む側と受ける側が、記録が残っていれば前後を
  読んで書く
- 2026-11-11 に、docs/adr の既にある ADR で括って引いたユーザーの言葉を、場面と意図の要約に直した（ADR-0065 の背景を含む
  24 ファイル）。直す前の文はこの日より前の git の履歴にある。凍結する部分の中の引用も直したのは、ユーザーの答えをもとに親が決めた
  例外（背景）で、決定の中身は変えていない。直した ADR のそれぞれには「## 変更」を足していない。要約は、記録が残っていたものは前後を
  読んで書き、残っていなかったものは引用と ADR の前後の文から書いた
- `claude-sync` は消したファイルを `~/.claude` から消さない（`--delete` を使わない）ので、`~/.claude/scripts/quote-in-transcript.sh`
  は反映の後も残る

### 確認

- delegate の `references/working.md` と `references/requesting.md` に、括った原文の引用を求める文と、引用を記録と照らす文が無い
- docs/adr に `「<引用>」（ユーザー <日付>）` の形の括った引用が残っていない（ほかの形の引用は 2026-11-11 に手で直し、この検査は拾わない）:
  `perl -Mutf8 -CSD -0ne 'print "$ARGV\n" if /「[^」]*」\s*（ユーザー\s*20/' docs/adr/*.md` の出力が空
- `.claude` と `modules` に `quote-in-transcript` を指す行が無い（`grep -rn quote-in-transcript .claude modules` の出力が空）

# ADR-0061: /delegate を呼ぶ Agent の依頼の欄を PreToolUse の hook で確かめる

## 背景

ADR-0060 は delegate の依頼の定型を 6 つの欄（リポジトリ、ブランチ、何をするか、前提、完成の形、変える範囲）にした。
事実は「前提」の欄に 1 行ずつ出典とともに書く。それでも、xlc のセッションで 2026-10-28 06:44 以降に親が書いた依頼文
5 本のうち 4 本に「前提」の欄が無く、1 本（brief-0145-ast-deps.md）には「完成の形」も無かった（#493）。

PR #492 は、頼む側の「前提」の項に規則の文を 1 つ足そうとして、閉じた（#493 の「試して捨てた方式」）。ADR-0060 が
退けた案 B（規則の文を足す）と同じ形で、今回は欄の規則そのものが破られていたので効かない、という指摘を受けた。

欄があるかどうかは、依頼の文字列だけで決まる。ほかの機械で判定できる禁止と必須は、hook が止めて、拒否の文言に理由と
修正方法を書いている（~/.claude/CLAUDE.md の「開発プロセス」）。親の依頼によれば、#493 の案 1（hook）は 2026-10-28 に
ユーザーが「推奨に従います」と答えて決まった。

依頼は 2 つの形で渡る。prompt に依頼文を直接書く形と、prompt に「依頼文は <絶対パス> にある。最初にそれを Read で読み、
冒頭の指示どおり /delegate を呼ぶ」と書いてファイルに依頼文を置く形。

## 検討した案

- 案 1: Agent の PreToolUse の hook（claude-hooks）で、/delegate を呼ぶ依頼の依頼文（prompt、または prompt が指す
  ファイル）の 6 つの欄の見出しを確かめ、欠けていれば欠けた欄の名前つきで止める（#493 の案 1）
- 案 2: delegate のスキルに依頼文を確かめるスクリプトを置き、送る前に実行する手順にする（#493 の案 2）。手順の文なので、
  ADR-0060 の案 B と同じく飛ばされうる
- 案 3: 受ける側が欄の無い依頼で止まる。ADR-0060 が案 C として退けた形で、前提の無い依頼にも往復が 1 回増える。
  hook は送る前に止めるので往復が無い

見出しの判定の形:

- 案 a: SKILL.md の定型の文字列どおり `前提:` だけを見出しとする。xlc の scratchpad にある親の依頼文のうち 8 本
  （brief-0181-erfcx.md、brief-0180-perf.md、brief-defaults.md など。2026-10-28 に `grep -l '^前提（'` で数えた）は、
  `前提（出典で確かめたもの）:` と `前提（確かめていない。確かめることが作業の一部）:` の 2 つの見出しで書いていた。
  これらは欄の規則を守っているのに止まる
- 案 b: 2 つの見出しを定型に入れる。ADR-0060 の定型（1 つの欄の各行に出典か「確かめていない」を添える）を変える決定で、
  この hook の決定とは別に扱う。この ADR では決めない（親の判断、2026-10-28）
- 案 c: 行頭が欄の名前で始まり、直後に `:` か `（…）:` が続く行を見出しとする。`前提:` と `前提（…）:` の両方を通し、
  ほかの 5 つの欄も同じ規則にする
- 案 d: 案 c に加えて、全角の `：`、Markdown の見出し（`## 前提`）、太字（`**前提**:`）、字下げした行も見出しとする
  （ローカルレビューの指摘）。定型の形（行頭の名前と `:`）と違う書き方まで定型として扱うことになり、スキルの定型と
  hook の判定が分かれる。拒否の文言が見出しの形を示すので、違う形で書いた依頼も 1 回で直せる

対象の決め方:

- 対象は、prompt か依頼のファイルの空でない最初の行に「/delegate を呼び」（呼ぶ、呼んで）に句読点か行末が続く句がある
  呼び出しにする。定型の 1 行目がこの句。句読点まで見るのは、「呼ぶ必要はない」「呼びません」を数えないため。`/code-review`、`/retro`、Explore などへの依頼は欄を持たないので、Agent の呼び出しをすべて確かめると
  誤って止める
- 最初の版は、prompt のどこかに `/delegate` の語（`/delegated` やパスの一部を除く）があれば対象にした。ローカルレビューで、
  /delegate を調べる依頼、/delegate を呼ばない文、SKILL.md の差分を引用するレビューの依頼を止め、エスケープが無いので
  文言を変えるほかに通す方法が無いこと、/delegate の指示がファイルの側にしかない依頼（「依頼文は <パス> にある。Read で
  読んで従う」）を見逃すことを指摘され、1 行目の句に改めた
- ファイルを指す形は、prompt の空でない最初の行の「依頼文は <絶対パス> にある」の句で見分ける（パスは `` ` `` か「」で
  囲んでもよい）。prompt に出る絶対パスを片端から読むと、リポジトリのパスなど依頼文でないものを読む。最初の版は句を
  prompt のどこにあっても使い、前提の欄で別の依頼文に触れた完全な依頼をそのファイルで判定するとローカルレビューで
  指摘されたので、1 行目に限った
- 依頼のファイルの 1 行目が「# brief-…」のような表題で始まり、prompt も /delegate を呼ばないと、対象から外れる
  （ローカルレビューの指摘）。定型の 1 行目は /delegate を呼ぶ句なので、定型の外の書き方として扱い、判定を広げない

作らなかった検査:

- 「何をするか」の本文の単位つきの数（秒、分、倍、pcm など）を「前提」の欄へ移すよう警告する（#493 の両案に付いた案）。
  本文には決定の出典の日時（「2026-10-28 08:14」）、ADR と issue の番号、回数の上限など、事実の値でない数も入り、誤検出の
  扱いが決まっていない（#493）。この ADR では作らない

hook に届く tool_name:

- 両方の名前（`Agent` と、旧名とされる `Task`）を受ける形は採らない。xlc のセッションの記録
  （~/.claude/projects/-home-tagawa-github-xlc/ の最新の jsonl、Claude Code 2.1.312）で、サブエージェントを起動した
  tool_use の name は 91 件すべて `Agent` だった。hook の入力の tool_name はこの名前なので、`Agent` だけを見る

## 決定と理由

採用: 案 1 と案 c。

- claude-hooks に、ツールの名前を持つルール `delegate-request-fields` を足す。ルールは検査するツールの名前を持ち
  （既定は Bash）、hook は入力の tool_name と同じツールのルールだけを評価する
- 対象: prompt か依頼のファイルの空でない最初の行に「/delegate を呼び」（呼ぶ、呼んで）がある Agent の呼び出し。
  依頼のファイルが読めないときは、prompt の 1 行目に句があれば止め、無ければ対象と決められないので通す
- 依頼文: prompt の空でない最初の行に「依頼文は <絶対パス> にある」があれば、そのファイル。絶対パスでないとき、通常の
  ファイルでないとき（FIFO などを読むと hook が止まる）、1 MiB を超えるとき、読めないときは、そのパスと理由を書いて
  止める。無ければ prompt
- 見出し: 行頭が欄の名前（リポジトリ、ブランチ、何をするか、前提、完成の形、変える範囲）で始まり、直後に `:` か
  `（…）:` が続く行。箇条書きの中や、コロンの無い行は数えない
- 欠けた欄があれば止め、拒否の文言に欠けた欄の名前、欄が要る理由、判定の規則、修正方法を書く。欄の中身（出典の有無）は
  判定しない
- エスケープは設けない。欄を足す以外に直す方法が無く、事実を使わない依頼も `前提: なし` と書ける
- settings.json の hook の登録を、バイナリだけを持つ matcher `Bash|Agent` の組にする（claude-code.nix）。最初の版は
  バイナリのある組の matcher を書き換えたが、同じ組のほかの hook も Agent で走るとローカルレビューで指摘され、既にある
  登録を外して足し直す形にした
- delegate のスキルの頼む側の節には、見出しの形と、hook が欠けた欄で止めることを書く。見出しの形は定型の一部なので
  スキルに置き、hook の判定と同じ規則にする（ADR-0044 の「hook が強制することは書かない」は、規則の文を二重に置かない
  ためのもので、定型の形を書くことは妨げない）

案 2 と案 3 を採らない理由は上のとおり。案 a は欄の規則を守る依頼を止め、案 b はこの決定の外になり、案 d は定型と判定を分ける。

### 帰結

- 欄の無い依頼は送る前に止まり、親が欄を書いてから呼び直す。受ける側の手順 1 の「前提の欄が無い」の報告（ADR-0060）は、
  hook を通らない経路（hook の登録の前の環境など）の安全網として残る
- 欄の中身と、本文に散った事実は確かめない。それは今までどおり書く側と受ける側の確認に任せる
- hook の登録を変えるので、効くのは home-manager の switch の後

### 確認

- `cargo test` の `rules::delegate_request_fields` のテストが、欄がそろう依頼を通し、欠けた欄を名前つきで止め、ファイルを
  指す依頼でファイルを読み（無ければ止め）、/delegate に触れるだけの prompt を見ないことを示す
- `tests/delegate_request.rs` が、バイナリを通して Agent の呼び出しだけに検査が掛かることを示す
- `rules::tests` が、Agent では `delegate-request-fields` だけを、Bash ではそれ以外のルールを評価することを示す
- claude-code.nix の PreToolUse の登録が、バイナリだけを持つ matcher `Bash|Agent` の組であることを、switch の後の
  `~/.claude/settings.json` で読んで確かめる（登録の jq を検査するテストは無い）

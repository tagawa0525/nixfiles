# ADR-0001: ホストの間で共有する秘密は sops-nix で配る

## 背景

ノート PC（t14g4、x1ng1）から r995 の Slurm にジョブを投入するには、全ホストで同じ munge の鍵が要る。nixfiles には
秘密を配る仕組みがなかった。鍵を nix のストアに入れると、ストアは誰でも読めるので秘密にならない。

- 秘密を nix のストアに入れないこと
- 鍵の配り方を宣言的に管理でき、ホストを足したり鍵を替えたりできること
- 依存と運用の手間を増やしすぎないこと

## 検討した案

- 案 A: r995 で作った鍵を、SSH で一度だけ手でほかのホストにコピーする。仕組みは足さないが、ホストを足すときや鍵を
  替えるときの手順が宣言的に残らず、手で揃える必要がある
- 案 B1: agenix。秘密 1 つにつき age で暗号化したファイル 1 つ。仕組みが小さく、任意のファイルをそのまま扱える
- 案 B2（採用）: sops-nix。SOPS の形式で値ごとに暗号化し、1 つのファイルに複数の秘密を置ける。秘密が変わったときの
  サービスの再起動、テンプレート（秘密を埋め込んだ設定ファイル）、バイナリの秘密を扱える

## 決定と理由

案 B2 にする（ユーザーの判断）。今後ほかの秘密（API の鍵、サービスのパスワードなど）を足すとき、1 つのファイルに
まとめられ、テンプレートも使えるので伸びしろがある。NixOS で広く使われていて、情報も多い。

- **復号の鍵**: 各ホストの SSH のホスト鍵（`/etc/ssh/ssh_host_ed25519_key`）を age に変換して宛先にする。新しい
  秘密の鍵をホストに置かずに済む
- **編集する人の鍵**: 既存の `~/.ssh/id_ed25519` を age に変換して宛先にする。編集のときは
  `SOPS_AGE_KEY_CMD="ssh-to-age -private-key -i ~/.ssh/id_ed25519" sops <ファイル>` で復号する。新しい秘密の鍵を
  増やさない
- **置き場所**: 暗号化した秘密は `secrets/`、宛先の規則は `.sops.yaml`

## 確認

- munge の鍵（`secrets/slurm/munge.key`）を暗号化し、編集する人の鍵で復号して 1024 バイトに戻ることを確かめた
- r995、t14g4、x1ng1 の構成のビルドが通る

## 結果

- ホストを足したら、そのホスト鍵を age に変換して `.sops.yaml` に足し、`sops updatekeys <ファイル>` で暗号化し直す
- 編集する人の `~/.ssh/id_ed25519` を失うと、ホスト以外では秘密を編集できなくなる（ホスト鍵でも復号はできる）

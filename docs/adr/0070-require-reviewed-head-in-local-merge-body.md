# ADR-0070: ローカルのマージの本文にレビューした head と指摘ごとの再現の行を書かせ、hook が先端と照らす

## 背景

GitHub リモートの無いリポジトリは、/git-merge でブランチを main にローカルにマージする。/git-merge の「レビュー」の節
（ADR-0066）は、blocking を直したら直した差分を焦点にもう 1 周回すこと、/delegate の担当が示した最後の周の HEAD より後に
挙動を変える変更があれば回すこと、指摘ごとに「再現: …」か「再現なし → #…」をマージの本文に書くことを求める。
どれも文章の規則で、ローカルのマージを止める hook（`guard-git-merge`、`pre-git-merge-check`、`check-merge-body-ja-terms`、
git の pre-merge-commit）はレビューを見ない。

2026-10-31 に、xlc で親のセッションがこの規則から外れたマージを行った（/retro の 37 回目と 38 回目が見つけたと親の依頼に
ある。下は本文を `git show` で読んで確かめた文）:

- 08a7d1267: rebase の後に親が回した周で 2 件を直し、本文に「直した後の周は回していない」
- 5a78f7fa0: rebase の後に親が回した 3 周目の指摘（前段の語、settings の経路のテスト、127 のテスト）を直したと読め、本文に
  記録の周の記述が無い
- be942f6c2: 文書だけのブランチで、本文は「事実の確認のみで回した」で、回した周も最後の周の HEAD も書いていない
- 82bb48398: 本文に指摘ごとの「再現: …」「再現なし → #…」の行が無い（記録の周の候補 3 件を「#0190 に残し」と書く）

本文の書き方は自由で、0e269866a は「担当（Opus 5.5）のレビューは high で 3 周（最後の周は b7e01d512。1 周目: …（再現: …）…）」
の形で、最後の周の HEAD と再現を 1 つの文に入れていた。機械で読める形が無いので、外れても気づくのは後の /retro になる。

親が判断待ちの (11) としてこのゲートを示し、ユーザーは「gをお願いします。hookも足してください。」（ユーザー 2026-10-31）と
答えた（「hook」がこのゲートを指すことは親の依頼の説明による）。

GitHub の PR には同じ役の仕組みがある。ADR-0043 は、PR のコメントのローカルレビューの記録（`record-local-review.sh` の
`<!-- local-review sha=<head> high=0 -->`）が head にあればマージを通し、ADR-0059 は、記録の sha から rebase だけした head も
PR の差分を比べて通す。ローカルのマージには PR もコメントも無い。

## 決定の要因

- レビューの規則から外れたマージを、後の /retro でなくマージの時点で止める
- /git-merge の規則（最後の周より後の挙動を変える変更だけに回す、指摘ごとの再現を本文に書く）と同じ線で止め、規則に従った
  マージを止めない
- 記録は後から引ける場所に置く（どの head をレビューしたマージかを、マージの後に読める）
- 判定は機械で決まるものに限り、判断の要る部分（文書の変更が記録の数値を変えるか）はスキルに残す

## 検討した案

記録の置き場:

- 案 A（採用）: マージの本文。`git merge -m` / `-F` の本文は hook が組み立てられる（`check_merge_body_ja_terms.rs` の
  `merge_message`。git と同じ順で `-m` と `-F` をつなぐ）。本文は main の履歴に残り、`git log` で引ける。/git-merge は
  既に本文の Impact にレビューの周と指摘を書いている
- 案 B: git notes（`refs/notes/review` に、レビューした head へ記録を付ける。ADR-0043 のコメントの記録に近い）。notes は
  既定では push も clone もされず、`git log` に既定で出ない。親は本文にも同じことを書くので、記録が 2 か所に分かれる。
  記録を付ける手順（スクリプト）も増える
- 案 C: ファイル（`.git` の下や worktree）にレビューの記録を書く。履歴に残らず、後片付けで消える

本文の形:

- 案 D（採用）: 固定の行。`Reviewed: <hash>` の行を 1 つと、指摘ごとの行（`再現: …`、`再現なし → #…`、`前提が誤り: …`、
  `抜け道: …`）か、指摘が 0 件の `指摘なし` の行を 1 つ以上
- 案 E: 0e269866a の自由な文（「最後の周は <hash>」）を正規表現で拾う。言い回しが変わると拾えず、拾えないときに止めるか
  通すかを決められない

rebase で hash が書き換わったとき:

- 案 F（採用）: 親が `git range-diff` で対応を取った rebase 後の hash を本文に書き、hook は本文の hash と先端だけを照らす
- 案 G: hook が本文の hash（rebase 前）と先端を range-diff で比べる。range-diff の「同一」は、rebase で入った main の変更が
  ブランチの挙動に関わらないことまでは言わない（/git-merge の rebase 後の判断は、main の変更がブランチと同じファイルや
  関わる挙動に触れないかも見る）。ADR-0059 の PR の差分の比較（ADR-0021）は GitHub が返す base で比べるが、ローカルでは
  rebase 前の土台がブランチの履歴に残らない（reflog だけ）。判定の一部だけを機械に移すと、通ったことが rebase 後の判断を
  済ませたことに見える

最後の周より後のコミット:

- 案 H（採用）: 後のコミットが挙動を変えないファイルだけなら通し、ほかは止める。挙動を変えないものの線は下の決定に書く
- 案 I: 本文の hash がブランチの先端と一致するときだけ通す。/git-merge は挙動を変えない文書だけの後のコミット（ADR の帰結の
  直し、remap、relock）に周を回さないと決めているので、規則に従ったマージを止める
- 案 J: 後のコミットを見ない（本文の形だけを確かめる）。レビューの後に足したコードが通る
- remap の判定の作り直す前の版: 対の行が 16 進の語を除いて同じなら、どのファイルでも付け替えとして通した。ローカルレビューの
  1 周目で、依存の rev（`Cargo.toml` の `rev = "<hash>"`）、submodule の更新、テストの期待値の 16 進の定数の差し替えも同じ形で
  通ると指摘され、`Cargo.toml` の rev の差し替えが通ることをテストで再現した。続く版は、足した側の語が先端の祖先に解けることだけを
  求めた。2 周目で、既定ブランチのコミットへの差し替えと、ブランチのコミットどうしの差し替え（消した側も先端の祖先）が通ると
  指摘され、テストで再現した。消した側が先端の祖先でないことと、足した側が既定ブランチの祖先でないことを足した。
  付け替えを `.md` に限る案は、`commit-refs remap` が 16 進を含む追跡しているテキストのファイルをどれも書き換える（`remap.rs` の
  `candidate_paths`）ので、JSON などの記録の付け替えを止めるとして採らなかった

## 決定と理由

案 A、D、F、H にする。claude-hooks に `check-merge-review` のルールを足す。`pre-git-merge-check` に足さないのは、
そのルールのエスケープ（`ALLOW_MULTI_TOPIC`）がルールの全体に効く形（`Rule::escape`）で、別のエスケープを持つ検査を
同じルールに入れると、片方のエスケープで両方が外れるため。

**対象**: 既定ブランチへのローカルのブランチの `git merge`（`guard-git-merge` と同じ判定。中断・再開とリモート追跡ブランチの
取り込みは対象外）。1 つのコマンドで 2 本以上のブランチをマージするもの（octopus）は、本文の hash をどのブランチに当てるか
決まらないので止める。

**本文の必須の形**（`-m` / `-F` の本文。行の先頭の空白と `-` / `*` の箇条の印は除いて読む）:

- `Reviewed: <hash>` の行がちょうど 1 つ。hash は 7〜40 桁の小文字の 16 進で、最後のレビューの周を回した HEAD
  （/delegate の担当の報告の「最後の周を回した HEAD の hash」、親が自分で回したときは親の最後の周の HEAD）
- 指摘の行が 1 つ以上。指摘ごとに 1 行で、直した指摘は `再現: <テスト名 | 手順 | 出典>`、直さない指摘は
  `再現なし → #<issue の番号>`、前提が誤っていた指摘は `前提が誤り: <確かめた事実>`、hook の抜け道として扱う指摘は
  `抜け道: <理由>`（/git-merge と /delegate の報告の分け方と同じ 4 種）。レビューの全部の周で指摘が 0 件なら `指摘なし`
- 本文が決まらない形（`-m` / `-F` の無いもの、シェルが展開する値、読めない `-F` のファイル）は止める
  （`check-merge-body-ja-terms` は commit-msg が同じ検査をするので通すが、このルールの後ろには同じ検査が無い）

**止める条件**（エスケープなし。修正方法は拒否の文言に示す）: 上の形を満たさない、hash がコミットに解けない、hash が
マージするブランチの先端の祖先でない（rebase で書き換わった。range-diff で対応する hash を書くか、ブランチ全体を回す）、
hash が既定ブランチの祖先（ブランチのコミットでない）。

**最後の周より後のコミット**: `git diff <hash> <先端>` で変わったファイルが、どれも次のどれかなら通す。ほかがあれば止める。
エスケープは `ALLOW_UNREVIEWED_HEAD=<理由>`（GitHub の `pre-merge-check` の、レビューされていない head を通すものと同じ名前）で、
この検査にだけ効く。/git-merge の歯止めの 3 周を使い切った後の変更を未レビューとして Impact に書いてマージするときに、
規則に従ったマージを止めないため（ADR-0066 の「3 周目で blocking を直したら」の記録の周の後には付けない、は変わらない）。

- 文書: `.md` のファイルのうち、`.claude` のディレクトリの下でなく、名前が `CLAUDE.md` でも `SKILL.md` でもなく、
  `docs/adr/` の下でないもの。/git-merge は「挙動（コード、計算、hook の判定、テストの比べる範囲、スキルと hook の文書、
  記録の数値）を変える変更があれば回す」「挙動を変えない文書だけ（docs/ の説明、記録の本文など）なら回さず」と書く。
  スキルと hook の文書（`.claude/` の下と `CLAUDE.md`、`SKILL.md`）は挙動に数える。ADR は、/git-merge の「proposed の ADR」の段が
  「この段で直した ADR は、docs/ だけの変更でもレビューを受けさせる」と書くので数える
- DVC の記録: 名前が `dvc.lock` のファイルと `.dvc` で終わるファイル（rebase の後の /dvc-relock が書き直す。計算の入力の
  `dvc.yaml` は含めない）
- remap: どのファイルでも、`git diff -U0` のすべての hunk で、消した行と足した行が同じ数で、対の行が 16 進の語（a〜f を 1 字以上
  含む 7〜64 桁）を除いて同じで、変わった語の対がどれも、消した側が先端の祖先でない（rebase で書き換わって消えた）コミットか
  コミットに解けない語で、足した側がブランチのコミット（先端の祖先で、既定ブランチの祖先でない）に解けるもの（rebase の後に
  `commit-refs remap` が書き換える、記録の中のコミットの hash の付け替え）。
  hunk の無い変更（モードだけの変更、バイナリ）は remap に数えない。数字だけの語は数の変更と見分けられないので 16 進の語に
  数えない（数字だけの hash を付け替えたファイルは止める側に倒れる）

この線は hook の通す条件で、通ったことは規則を満たした証にならない。記録（`.md`）の数値の変更は機械で本文と見分けられないので、
/git-merge の「件名やファイル名だけで判断しない」と、`git diff <最後の周の HEAD> HEAD` を読む手順はスキルに残る。

**rebase の後**: 本文に書くのは rebase 後の hash で、親が `git range-diff <古い土台>..<旧先端> main..[branch]` で対応を取る。
hook は本文の hash と先端だけを照らし、range-diff の判定はしない（案 G の理由）。rebase の後に回すかの判断（range-diff の同一と
main の変更）は、今までどおり /git-merge の規則で親が決め、本文に根拠を書く。

**置き場と書き方**: `Reviewed:` は本文の末尾の `Branch:` の上に、指摘の行は Impact に箇条で書く（hook は本文のどこにあっても
読む）。GitHub の PR の流れ（ADR-0043、ADR-0059 の記録と判定）は変えないので、両 ADR の「## 変更」は要らない。

### 帰結

- 最後の周より後に挙動を変えるコミットを足したマージと、レビューの周や指摘の分け方を本文に書かないマージは、hook が止める
- 親は本文を固定の形で書く。0e269866a のような自由な文の「最後の周は <hash>」は `Reviewed:` の行に、「（再現: …）」は
  指摘ごとの行に置き換わる
- 本文の hash は自己申告で、その head に実際に /code-review を回したかは機械で確かめない（ADR-0043 の記録と同じ弱点）。
  止めるのは、書き忘れと、書いた head より後に挙動を変える変更を足したことである
- マージが拒まれた後の `git commit -m`（MERGE_HEAD の残るマージを本文を直して終える /git-merge の手順）は、このルールの
  対象でない。`git merge` の時点で本文を確かめ済みで、直すのは崩れた語だけのため
- 反映は nixfiles のマージの後の rebuild（home-manager の switch）で、それまでの claude-hooks は古いまま

### 確認

- `check_merge_review.rs` のユニットテスト 17 件（一時の git のリポジトリで判定する）: 先端と一致する hash と短い hash を通す。
  hash より後の文書、`dvc.lock`、`.dvc`、ブランチのコミットへの hash の付け替えだけの変更を通し、ブランチのコミットに解けない 16 進の語、既定ブランチのコミット、ブランチのコミットどうしへの差し替え、コードの変更、スキルと hook の文書、`CLAUDE.md`、
  ADR、`dvc.yaml` の変更を止める。エスケープは後のコミットの検査だけを外し、短い値には理由を求める。`Reviewed:` の行の欠け、
  重なり、hash でない値と、指摘の行の欠け（括弧の中の「（再現: …）」、値の無い行、番号の無い「再現なし →」）を止め、4 種の
  指摘の行と `指摘なし` を受ける。先端の祖先でない hash、既定ブランチの hash、解けない hash、本文の決まらない形（前段で書く `-F` のファイルには呼び出しを分ける案内）、2 本を 1 回で
  マージするものを止める。ヒアドキュメントの本文を読む。既定ブランチの外のマージと中断・再開は見ない。16 進の語の置き換えと
  hunk の対の判定

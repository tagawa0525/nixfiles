# ADR-0037: 振り返り（/retro）の入力に、会話の文脈に加えて Claude Code の会話の記録（transcript）を読む

## 背景

ユーザーは、作業の区切りに「ここまでの作業で、hook/script/skill/prompt/memory を削除・修正・追加したほうが良いものが
あれば改善してください」と定期的に頼みたい。これを /retro のスキルにする。

改善の手がかりは、ツールの失敗、hook の拒否、権限の拒否、ユーザーの訂正と好みで、多くは会話の文脈にある。ただし
文脈だけでは次が欠ける。

- サブエージェントの中の失敗。親の文脈に届くのは最後の報告だけで、途中の hook の拒否やツールの失敗は届かない。
  2026-10-20 のセッション（`8cb2c392-…`）はサブエージェントを 18 回起動し、その記録は
  `~/.claude/projects/<プロジェクト>/<セッション>/subagents/agent-*.jsonl` にだけある
- 要約（compact）の後の、要約より前の出来事
- 回数。同じ拒否が何回起きたかを、モデルが文脈から数えると落ちる（数えるのはスクリプトに置く）

Claude Code は、セッションごとの記録を `~/.claude/projects/<プロジェクト>/<セッション>.jsonl` に 1 行 1 イベントで書き、
Bash ツールの環境に `CLAUDE_CODE_SESSION_ID` を渡す（2.1.304 で確認）。ツールの結果は `type: user` の行の
`tool_result` で、失敗は `is_error: true`、hook の拒否は本文が `PreToolUse:Bash hook error:` で始まる。この形式は
公開の仕様ではなく、版の更新で変わりうる。

## 検討した案

- 案 A: 文脈だけを読む。サブエージェントの中の失敗と、要約より前の出来事を落とす
- 案 B: claude-hooks に拒否の記録（ファイルへの追記）を足す。hook の拒否だけで、ツールの失敗、権限の拒否、
  ユーザーの訂正は取れない。記録の置き場所、保持期間、セッションとの対応づけを新しく決めて保守することになる
- 案 C（採用）: 記録を読むスクリプトをスキルに置き、文脈と合わせて使う

## 決定と理由

案 C。記録はすでに書かれており、新しく保守するものが無い。サブエージェントの記録も同じ形で読め、hook の拒否以外の
失敗も 1 か所から取れる。

形式が変わる危険は、スクリプトが記録を読めないとき（`type` を持つ行が無い、ツールを呼んだ行があるのに
`tool_result` が無い）に失敗で止まることで、黙って 0 件と出さないようにして抑える。分類（hook、権限、ツール）を誤っても、件数と本文は残るので、
判断するモデルが読み直せる。

### 帰結

- `.claude/skills/retro/scripts/session-events.sh` が記録を読み、拒否と失敗を種類と本文ごとに数え、ユーザーの発言を
  順に出す
- Claude Code の更新で記録の形が変わったら、このスクリプトのテストの入力（記録の行）を新しい形に合わせて直す
- 記録は Claude Code の `cleanupPeriodDays`（既定 30 日）で消える。/retro は今のセッションを対象にするので足りる

### 確認

- `bash .claude/tests/scripts/retro.sh` が、作った記録の行から期待した件数と分類を出す
- 2026-10-20 のセッションの記録に対して実行し、文脈に無いサブエージェントの拒否が出る

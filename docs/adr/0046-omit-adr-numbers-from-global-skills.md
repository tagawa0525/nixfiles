# ADR-0046: PC 全体で読み込むスキル、スクリプト、CLAUDE.md には、nixfiles の ADR の番号を書かない

## 背景

`.claude/skills/`、`.claude/scripts/`、`.claude/CLAUDE.md` は `claude-sync` で `~/.claude` に配られ、PC 全体の
セッションで読み込まれる。ここに nixfiles の ADR の番号（`ADR-0043` など）が、28 ファイルの 70 か所にあった
（2026-10-21、#417）。hook の拒否メッセージ（`modules/home/parts/claude-hooks/src/rules/` の文字列）にも 3 か所あり、
どのプロジェクトのセッションにも出ていた。

nixfiles 以外のプロジェクトでは、番号の先を引けない。読み手に判断材料を渡さず、ノイズでしかない（ユーザーの指摘）。

## 決定の要因

- 読み手は nixfiles 以外のプロジェクトのセッション。番号の先が無くても、規則を守る判断ができること
- 番号を外すと、番号の先にしか書いていなかった理由が消えうる。消えないこと
- 同じ参照が再発しない仕組み

## 検討した案

- 案 A: 番号を全部外す。判断に要る理由は、その場に書く
- 案 B: 番号を、`nixfiles の docs/adr` のように場所で書く
- 案 C: 番号を残す。nixfiles のセッションでは引ける
- 案 D: スクリプトの出力と hook の拒否メッセージだけ残す。nixfiles の中でしか読まれない出力とみなす

## 決定と理由

採用: 案 A。

- 外す範囲は、スキル、スクリプト（コメントと出力）、`.claude/CLAUDE.md`、hook の拒否メッセージ。書式の例
  （`[ADR-NNNN]`）は、番号を `NNNN` にして残す。範囲の外は、Rust とテストのコメント、`docs/`、nixfiles の
  モジュール（読み手が nixfiles の開発者）
- 変えた行をすべて読み、番号の先にしか書いていなかった情報は、その場に書いた。マージの直前で止めるのを依頼より優先する
  理由（サブエージェントの報告は確かめる前の暫定）、hook のエスケープを依頼に書かない理由（条件を書くと、それに合わせた
  無意味な値を誘う）、文書だけの PR で直すものを絞る理由（文章は細部をいくらでも掘れるので、周回が収束しない）、Slurm の
  優先度の式の出典（`PriorityWeight*` の設定）。抜け道の指摘を直さない規則には、理由と「普通に書く形」の定義
  （ふつうの手順で書くコマンド）を足し、delegate、gh-pr-create、gh-pr-review、git-merge の 4 ファイルに同じ内容を書いた。
  残りは、番号が出典を示すだけで、規則と理由は文の中にあった
- 案 B は、場所を書いても、ほかのプロジェクトでは引けない。案 C は、ノイズが残る。案 D は、拒否メッセージが
  nixfiles の外のセッションにも出ること（実際に出た）と、スクリプトの出力が同じ読み手に届くことを見落とす
- 再発は `.claude/tests/skills.sh` が防ぐ。上の範囲に `ADR-0123`、`adr-0123`、`ADR 0123`、`docs/adr/0123-…` の形があれば失敗する。
  hook の拒否メッセージは、複数行の文字列の継続行も見て、コメントとテストのモジュールは見ない

### 帰結

- 良い点: ほかのプロジェクトのセッションで、引けない参照を読まされない
- 悪い点: nixfiles の開発者が、規則の出典の ADR を、スキルから直接引けなくなる。出典は `git log -S` と
  `docs/adr/` の全文検索で辿る。コミットの本文と ADR からスキルへの参照は残る

### 確認

- `.claude/tests/skills.sh`: スキル、スクリプト、`.claude/CLAUDE.md`、hook の拒否メッセージに ADR の番号が無い

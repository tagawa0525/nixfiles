# ADR-0060: 依頼の定型に前提の欄を足し、事実を 1 行ずつ出典とともに書く

## 背景

ADR-0044 は、delegate の依頼の定型を「リポジトリ」「ブランチ」に続く 3 つの欄（「何をするか」「完成の形」「変える範囲」）で
書くと決めた。依頼に事実として書く値と前提は、頼む側が出典で確かめて添え、受ける側も作業の前に確かめる（ADR-0054）。
PR #481 は、出典を依頼を書く時点で開いた文書か実行したコマンドの出力にする、と足した。

それでも xlc で 2026-10-22、10-23、10-24 と 3 度、出典を開かずに書いた前提が誤っていた（#482）。2026-10-24 の依頼は、
確かめていない前提（「H の自由気体は OpenMC と同じ扱い」。OpenMC 0.15.2 は H in H2O の S(α,β) を 10 eV まで使う。xlc の
ADR-0133）と、検証の記録で書き直された古い値（1C の k の差の、燃焼度 0 の点からの変化の +147 pcm。xlc の bda07c3c7 で書き直された）を「何をするか」の
本文に散らして書いた。担当は手順 1 で出典と照らして食い違いに気づき、止まった。本文に散った事実は、書く側が 1 つずつ
出典を開いたかを自分で見返せず、受ける側も本文から事実を拾い出さなければ確かめられない。

PR #481 の最初の版は定型に「前提」の欄を足したが、ADR-0044 が欄を 3 つと決めていること、冒頭の説明と argument-hint が
欄を列挙していること、受ける側の手順 1 が「確かめていない」と添えた値を「前提ではない」と書いていること、本文と欄の
両方に同じ事実を書くとずれることをローカルレビューで指摘され、外した（#482）。同じレビューで、出典の規則について
3 件が残った（#482 のコメント）: 前に終わった長い計算の結果を出し直せとも読める、決定の根拠の「ユーザーの言葉」と
「会話で前に見た値を出典にしない」の関係が書かれていない、例が xlc の語に寄り日付つきの例が増え続けている。

ユーザーの言葉（2026-10-24、/retro の推す案（定型に前提の欄を足す）に対して）: 「それでいいです」。欄が無い依頼の扱いと
受ける側の確認の範囲は、この ADR の依頼で親が推した形（案 F）を、ローカルレビューの指摘で作り直したもので、ユーザーの
言葉はこの部分には無い。

## 検討した案

- 案 A: 定型に「前提」の欄を足す。依頼が事実として使う値と前提を 1 行に 1 つ、出典（依頼を書く時点で開いた文書の場所か、
  実行したコマンドとその出力）か「確かめていない」を添えて書く。「何をするか」には事実を書かず、要るときは前提の行を指す。
  受ける側は手順 1 で欄を順に出典で確かめ、欄の外に残った事実も ADR-0054 のとおり確かめる。欄が無い依頼は、報告の冒頭に
  「前提の欄が無い」と書いて進める
- 案 B: 欄は足さず、頼む側の書き方に「送る前に前提を列挙して出典を開く」手順を足す（#482 の別案）。列挙が依頼に残らないので、
  受ける側も親も漏れを見返せない。今の規則の文を足しても 3 度破られている
- 案 C: 案 A で、欄が無い依頼は受ける側が親に確認を返して止まる。前提の無い依頼でも往復が 1 回増える。欄が無くても、本文の
  事実は ADR-0054 の確認で作業の前に拾えるので、止まる必要がない
- 案 D: 案 A で、欄が無い依頼は「前提: なし」として黙って進める。親が欄を書き忘れたことに気づけない
- 案 E: 案 A で、事実を「何をするか」の本文にも書いてよいとする（PR #481 の最初の版）。片方だけ直って食い違う
- 案 F: 案 A で、受ける側の手順 1 は欄の行だけを確かめ、欄が無い依頼は本文から前提を探さずに進める（この ADR の依頼で
  親が推した形。ローカルレビューで作り直す前の版）。2026-10-24 の依頼は欄が無く、本文の誤った前提は ADR-0054 の確認で
  作業の前に止まった。この形ではそれが作業の後の報告の 1 行になり、追加の指示（欄が無い）、案に含まれる事実、「前提: なし」と
  書いた依頼の本文の事実も確かめなくなる。ADR-0054 と ADR-0055 の受ける側の決定を狭めることにもなる

## 決定と理由

採用: 「案 A」。

これは ADR-0044 の「依頼のテンプレートは「何をするか」「完成の形」「変える範囲」で書く」の部分を置き換え、「何をするか」の
後に「前提」の欄を足す。ほかの部分（することを肯定形で書く、完成の形まで作る、範囲の外の変更を分けて書く）は変わらない。
また、ADR-0027 の補足（2026-10-22）の「途中で止まった理由だけは本文に節が無いので要点に書く」の部分を置き換え、最初の依頼に
欄が無かったことも要点に書く。

- 欄は「何をするか」から事実を分けるためのもの。決定済みの内容（どこで決まったかを添える）、判断の軸、
  「案（決定ではない）」と親の評価（ADR-0055）は「何をするか」に残し、評価が使う事実は欄に書く。本文で事実が要るときは、
  前提の行の語をそのまま書いて指す。ユーザーの言葉は決定の出典で、事実の出典ではない（「会話で
  前に見た値」を出典にしない規則は、値と前提にだけ掛かる）
- 1 行に 1 つ書き、各行に出典か「確かめていない」を添える。事実を使わない依頼は「前提: なし」と書く
- 出典は依頼を書く時点で開いた文書か、実行したコマンドの出力。前に終わった計算の結果は、保存されたログや記録を開き直せば
  よく、計算をやり直さない
- 出典の規則（種類ごとの出典の形、出力なら切り替える入力の項目と設定まで読む）は頼む側の「前提」の項の 1 か所に置き、
  定型と受ける側の手順 1 はそこを指す。この項にあった日付つきの事例は、この ADR、ADR-0054 の背景、ADR-0027 の補足に置き、スキルには
  理由だけを残す
- 受ける側は手順 1 で欄の行を順に、同じ規則で出典と照らす。食い違うか出典が見つからなければ止まる。
  「確かめていない」と添えた値は、作業の前に止まる対象でなく、確かめることが作業の一部で、結果を報告に書く。作業中に
  誤りと分かり、それに頼った作業が成り立たなくなれば、案の反例（ADR-0055）と同じくその時点で止まる
- 欄の外（「何をするか」の本文、案、追加の指示、欄の無い依頼）に事実として書かれた値と前提のうち、ADR-0054 の種類で
  判断の前提にするものも、ADR-0054 のとおり作業の前に確かめ、確かめたものを報告に書く。欄は書く側の漏れを減らす仕組みで、受ける側の確認の範囲は狭めない
- 最初の依頼に欄が無ければ、報告の「親が先に読む要点」に「前提の欄が無い」と書いて進める（親が次の依頼で欄を書くため）。
  追加の指示は欄を持たないので、その事実は欄の外のものとして確かめる。出典が添えてない行は、受ける側が確かめたうえで、
  その行と見つけた出典を報告に書く
- 時間や精度の目標の内訳など、ほかの項目が依頼に書かせる事実も「前提」の欄に書く

案 B は依頼に列挙が残らず、見返せない。案 C は前提の無い依頼にも往復を足す。案 D は書き忘れが親に届かない。案 E は
二重の記述がずれる。案 F は、この ADR が防ぎたい誤りを作業の前に止めていた確認を外す。

ADR-0055 が「案」の欄を足さなかった理由（案は「何をするか」の一部）は、この決定でも変わらない。前提は「何をするか」の一部で
なく、それを支える事実なので欄を分ける。

### 帰結

- 依頼が 1 欄長くなり、書く側は事実ごとに出典を 1 行書く
- 受ける側は、欄の行に加えて欄の外の事実も確かめるので、確認の手間は減らない。減るのは書く側の漏れ

### 確認

- `.claude/skills/delegate/SKILL.md` の冒頭の説明、argument-hint、頼む側の定型が「前提」の欄を持ち、出典の規則が頼む側の
  「前提」の項の 1 か所にある
- 受ける側の手順 1 が欄の行を順に出典で確かめ、欄の外の事実も確かめ、欄が無い依頼の扱い（報告の冒頭に書いて進める）を持つ
- 報告の「親が先に読む要点」が「前提の欄が無い」を、「確認の結果」が出典の無かった行と「確かめていない」の結果を持ち、
  時間や精度の目標の内訳を「前提」の欄に書く

## 補足

- 2026-10-28: 頼む側の書き方に、前提のうち比を掛けた見込みの書き方（比の元の測定と、何と何の比かを添え、分子は見込む計算と、
  分母は比を掛ける測定と同じ条件の比だけを使う）を足した。決定（各行に出典か「確かめていない」）は変えず、出典の
  形の細部にあたる。xlc の ADR-0209 の依頼で、S(α,β) と自由ガスの比 1.3〜1.7 倍（xlc の ADR-0205 の担当の報告にあった
  `--timed` でない目安で、記録と ADR には無い）と、静止した標的の測定（2A の集合体の燃焼の
  ジョブ 18 分 58 秒、うち自己遮蔽の和 787.3 秒）から、出し直した依頼で 2A の集合体の燃焼を 30〜50 分と「確かめていない」を添えて書いた（比のほかに
  何を掛けたかは依頼に無い）。分母が自由ガスで、掛けた測定の静止した標的と違っていた（分母の合う比を使えば
  当たったかは確かめていない。xlc の ADR-0209 は、2A と 1C の 1 回がほぼ同じで大きさに釣り合わないとし、原因の候補を #0180 とする）。実測（xlc f434af311、
  2026-10-28、Slurm 563 と 565 の `--timed`。xlc の ADR-0209 の帰結と examples/depletion/verification.md）は、1 回の自己遮蔽が
  1C の 1 リングで 8.5 → 76〜77 秒（約 9 倍）、2A で 9.7 → 74.4〜77.0 秒（7.7〜7.9 倍）、2A の集合体の燃焼のジョブ（lattice と比較のステージの和）が
  1 時間 47 分 59 秒で、見込みの 2.2〜3.6 倍だった
- 2026-10-28: 頼む側の書き方の出典の規則に、測った値を入力やケースの値として書くときは、出した計算（ジョブかログ）と
  その計算が読んだ入力のファイルを出典に添え、文書の呼び名から入力を推して結びつけない、と足した。決定（各行に出典か
  「確かめていない」）は変えず、出典の形の細部にあたる。xlc の #0180 の依頼（2026-10-28）で、親は xlc の ADR-0209 の帰結の
  「1C のピンセルの 1 リングで 8.5 → 76〜77 秒」（燃焼の入力。81 核種、格子点 88 万、Slurm 563）を、同じ ADR の確認が
  「1C のピンセルの新しい燃料」と呼ぶ別の入力（`issue-0133/pin-1C-0.toml`。担当の報告で 32 核種、32.6 万点）の値として、「何をするか」の
  手順の本文に書いた。担当は手順 1 で食い違いに気づき（そのピンセルの減速計算は手元で 5 秒ほど）、燃焼の入力を燃焼度 1 点に
  した入力で内訳を測った。値は欄の外の本文にあり、欄の規則も破っていた

# ADR-0065: 依頼で括るユーザーの言葉は会話の記録からコピーし、受ける側が記録で確かめる

## 背景

delegate の頼む側の書き方は、決定済みの内容に、どこで決まったか（ADR などの記録の場所、ユーザーの言葉）を添えるとしていた。
ユーザーの言葉は決定の出典で、事実の出典ではない（ADR-0060）。ユーザーの案は「案（決定ではない）」として渡す（ADR-0055）。
ユーザーの言葉をどの形で書き、受ける側がどう確かめるかは決めていなかった。

2026-10-29 に xlc の依頼（#0188 の ADR の受理）が、2026-10-27 のユーザーの発言を「」で括って書いた。会話の記録の原文は
「MOXの燃焼は流す準備だけしておいて。今週のWeekly Limitが消えそうになったときのネタに取っておきましょう。（AWSで流さなくても
いいです。）」（ユーザー 2026-10-27。その会話の記録の `.jsonl` の `timestamp` 2026-10-27T14:12:02.931Z）で、依頼の言葉は語尾が「取っておく」に変わり、
後半が欠けていた。担当は括った言葉を原文として作業中の xlc の ADR-0206 に書いた（コミットされた版には入っていない）。
そのあとリポジトリとメモリで原文を探して見つけられず、要約に書き直した。会話の記録は探さなかった。担当が気づかなければ、
言い換えがユーザーの発言として確定した ADR に残った。

サブエージェントの文脈に親の会話は無いが、会話の記録のファイル（`~/.claude/projects/<プロジェクト>/<セッション ID>.jsonl`）は
Read と `jq` で読める。記録は 1 行 1 JSON で、ユーザーが打った発言は `type` が `user` で `origin.kind` が `human` の行と、
ターンの途中に送った発言の `type` が `attachment` で `attachment.type` が `queued_command` の行に入る。`user` の行には、
ツールの結果、ほかの担当の報告（`origin.kind` が `peer`）、会話の圧縮の要約とコマンドの出力（`<local-command-stdout>` など。
どちらも `origin` が無い）も入り、`human` の行にも IDE の通知や command-message（`<ide_opened_file>` など、`<` で始まる要素）が
入る。スラッシュコマンドに付けた言葉は `<command-args>` の中にある。`origin` の無い `user` の行（`/compact` などローカルの
コマンド、別のクライアントやモードの発言）は拾わないので、その発言の引用は要約に落ちる。
ユーザーが貼り付けた文は `<pasted_content …>` の中にあり、エージェントの出力を含みうるので、ユーザーの言葉に数えない。
Claude Code は古い記録を消す（`cleanupPeriodDays`）。圧縮の要約は上の発言を引用しており、`grep` で文字列を
探すだけでは、ユーザーの発言と要約を見分けられない。記録のファイルは、会話を始めたディレクトリ（worktree を含む）ごとの
ディレクトリに会話ごとにあり、ファイル名の ID は `Claude-Session:` の ID と別である。

## 検討した案

- 案 A: 「」で括る言葉は、会話の記録からコピーしたものだけにする。retro の `session-events.sh` の `USER:` の行（圧縮の
  要約や前の依頼を拾わない）からコピーし、文の途中で切らず、時刻を JST で添える。受ける側は時刻つきの引用だけを引く。
  ローカルレビューで反例が出た: `USER:` の行は 300 字で切れ、改行を空白にするので原文でない
- 案 A': 「」で括る引用には、会話の記録の `.jsonl` のパスと発言の `timestamp` を添え、記録からそのままコピーする。受ける側は
  `.jsonl` のユーザーの発言の行に同じ文があるかを確かめ、無ければ要約として書いて報告する。記録からコピーしない言葉は括らず、
  要約と分かる形で渡す
- 案 B: 依頼ではユーザーの言葉を括らず、判断の要約と発言の日付で渡す。受ける側は親の要約として書く。最初はこの案で書いたが、
  前提の「サブエージェントは会話の記録を見られないので、引用を確かめられない」が誤りだった（retro の担当とレビューの担当が
  `.jsonl` を読み、2026-10-27T14:12:02Z の発言を照らした）。前提が崩れると、要約に落とす利点は残らず、ユーザーの原文が
  委任した ADR に入らなくなる損だけが残る
- 案 C: hook（delegate-request-fields）で、時刻の無い「」の引用や、会話の記録に無い引用を止める。依頼の「」はユーザーの
  言葉以外（語、ファイルの見出し）にも使うので、ユーザーの言葉の引用を形から見分けられない

## 決定と理由

ユーザーの言葉は「」で括った原文で書かず、どの場面で何を求めたかを要約で書く（2026-11-11 に案 A' から変えた。前の決定と
変えた理由は「## 変更」）。会話の中の発言は前後のやり取りで意味が決まるので、原文だけを置くと誤解されやすい。

- 頼む側: ユーザーの言葉（判断、承認、案）は括らず、場面と意図の要約を `<要約>（ユーザー <日付> の発言の要約）` の形で書く。
  出どころを示すときは、会話の記録の `.jsonl` のパスと時刻を添える
- 受ける側が ADR や issue に書く形は、括らない `<要約>（ユーザー <日付>）` とする。日付は JST（記録の `timestamp` は UTC）
- delegate の受ける側の「ユーザーの承認は、ユーザーの言葉があるときだけ書く」は、「依頼と追加の指示がユーザーの言葉として
  書いたときだけ書く」にする。依頼そのものは承認ではない、という趣旨は変えない

### 帰結

- 委任で書いた ADR と issue には、ユーザーの判断が場面と意図の要約で入り、原文は入らない。原文を読みたいときは、添えた
  記録のパスと時刻から前後のやり取りごと読む（Claude Code は古い記録を消すので、消えた後は要約だけが残る）
- 頼む側が記録から原文をコピーし、`timestamp` を引く手間は無い
- 要約の誤り（引用に無い意図を足す、条件を落とす）は、機械では見つからない。頼む側と受ける側が、記録が残っていれば前後を
  読んで書く

### 確認

- delegate の `references/working.md` と `references/requesting.md` に、括った原文の引用を求める文と、引用を記録と照らす文が無い
- docs/adr に括った引用の形が残っていない:
  `perl -Mutf8 -CSD -0ne 'print "$ARGV\n" if /「[^」]*」\s*（ユーザー\s*20/' docs/adr/*.md` の出力が空

  前は「頼む側は、記録のパスと `timestamp` を、`~/.claude/projects/*/*.jsonl` に受ける側と同じ `jq` のコマンドを掛けて引く」

  頼む側はスキルの中の受ける側の節を探してコマンドをコピーすることになる。入力が決まれば結果が決まる手順は script に置く
  （`.claude/README.md` の「役割の分担」。ユーザーは、レビューの周の扱いについての親の推奨におおむね同意したうえで、規則をスキルの
  文より hook や script に寄せる方がよいのではと問うた（ユーザー 2026-11-08））
- 2026-11-11: 決定と理由、帰結、確認を、括った原文の引用から、場面と意図の要約に変えた。前の決定は「案 A'。ユーザーの言葉は
  原文で残し、言い換えを括った誤りは、受ける側が記録で機械的に見つける。」で、項は、頼む側が括る引用を記録からそのまま
  コピーして `.jsonl` のパスと `timestamp` を添えること、受ける側が `.claude/scripts/quote-in-transcript.sh` で同じ文が同じ発言に

  `「<引用>」（ユーザー <日付>）` と `<要約>（ユーザー <日付>）` の 2 つにすることだった（全文はこの日より前の git の履歴）。
  ユーザーは、指示の見直しの結果を xlc の親が報告した場面で、自分の発言を文脈から外して原文のまま書くのをやめ、意図を読み
  取って書くよう求めた。会話の中の発言は前後のやり取りで意味が決まるので、原文だけを置くと誤解されやすい、という理由
  （ユーザー 2026-11-11。nixfiles の #667 の「追加の提案: ユーザーの言葉は、原文のコピーでなく意図で書く形を基本にする」に
  xlc の親が書いた要約。この変更の担当は xlc の記録を確かめていない）。案 A' が防いだ誤り（親の言い換えを原文として括る）は、
  括らなければ起きない。要約の誤りを機械で見つける手段は無くなる（帰結）
- 2026-11-11: `quote-in-transcript.sh` とそのテストを消した。役目だった引用の一致の確認が無くなり、ほかに呼ぶものが無い。
  記録のパスと時刻から発言とその前後を出すツールに作り替える案は採らなかった。今の script は文で発言を探す形で、時刻で前後を
  出すには作り直しになり、その用途は `jq` か Read で記録を開けば足りる（必要になるまで作らない）

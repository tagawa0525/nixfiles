# ADR-0053: Slurm のジョブを既定で割り込まれうる main に置き、時間を記録するジョブだけを --timed で割り込まれないパーティション timed に投げる

## 背景

ADR-0052 は、r995 の Slurm に `preempt/partition_prio` と `PreemptMode=SUSPEND,GANG` を入れ、既定のパーティション `main`
（`PriorityTier=1`）のジョブを、`slurm-run.sh --urgent` で投げたパーティション `urgent`（`PriorityTier=2`、`PreemptMode=OFF`）の
ジョブが止める（SUSPEND）ようにした。止められたジョブは TIME 行に印を付け、`slurm-history.sh` が `sacct` の `Suspended` で
見分けて表から除く。時間を記録する測定も止められうるとし、割り込めないパーティションに分ける案（ADR-0052 の案 I）は、
「長いジョブの多くが測定なので、急ぐジョブがそれを待つことになる」として採らなかった。

2026-10-23 の深夜に、高速化の測定のジョブが、優先の低いテーブル作成のジョブの後ろで待たされた。担当（サブエージェント）が
`--urgent` を付けて投げ直そうとすると、セッションの許可の分類器に「走っているものへの干渉」として拒まれた（親のセッションの
依頼による。この ADR では確かめていない）。ADR-0052 の形では、割り込むことを投げる側が選ぶので、その操作は「ほかの
ジョブを止める」ことになる。

ユーザーは同じ夜に「run script に書くべき。デフォルトは割り込み可能にして、時間記録が必要な場合だけ割り込み禁止にするべき」と
指示した。割り込まれて困るのは、時間を記録するジョブだけである。それ以外のジョブ（テーブル作成、精度の記録、確認の計算、
参照解）は、止められても続きから再開し（ADR-0052）、結果は変わらず、終わりが遅れるだけである。

今の設定（2026-10-23、r995 の `scontrol show partition` と `scontrol show config`）は、ADR-0052 のとおり `main` と `urgent` の
2 つのパーティション（どちらも `OverSubscribe=FORCE:1`）、`PreemptMode = GANG,SUSPEND`、`PreemptType = preempt/partition_prio`
である。走っている排他の `main` のジョブ（505）の `squeue -o %h` は `NO` で（ADR-0041 の hook の判定は変わらない）、
`sacct` の `Suspended` が 0 でないジョブ（498）が 1 件あり、割り込みは働いている。

slurm.conf は Nix のストアに置かれ、Slurm の命令は `SLURM_CONF` にそのパスを埋めたラッパー（`wrappedSlurm`）から呼ばれる。
slurmctld と slurmd の `ExecStart` はそのラッパーを指すので、slurm.conf を変えると `nixos-rebuild switch` が 2 つを再起動する
（2026-10-23、r995 の `systemctl show slurmctld` とラッパーの `bin/sbatch`）。

## 決定の要因

- 時間を記録するジョブが、優先の低いジョブの後ろで待たず、走り出したら止められないこと（ユーザーの指示）
- 投げる側が「ほかのジョブを止める」ことを選ばずに済むこと。flag は自分のジョブの性質（時間を記録するか）だけを書く
- 割り込まれうるジョブの時間を、黙って記録に使わせないこと。flag の付け忘れ（時間を記録するつもりのジョブを flag なしで
  投げる）を、TIME 行と `slurm-history.sh` で見えるようにする（ADR-0029、ADR-0052）
- 止めたジョブの計算が無駄にならないこと（ADR-0007、ADR-0052）
- 仕組みを増やさないこと。`slurm-history.sh` の `sacct` の照合のように、要らなくなったものは消す

## 検討した案

守るジョブの選び方:

- 案 A（採用）: 既定（flag なし）は `main`（割り込まれうる）。時間を記録するジョブだけを `--timed` で、割り込まれない
  パーティションに投げる。急ぐ短い計算も `--timed` で投げる（`--urgent` は `--timed` にまとめる）
- 案 B: ADR-0052 のまま（既定は割り込まれないものとして扱い、`--urgent` が割り込む）
- 案 C: 3 層にする。時間を記録する長いジョブ（本番の燃焼）の上に、測定のためのさらに高い層を置く
- 案 D: `--timed`（割り込まれない）と `--urgent`（割り込むが、自分は割り込まれうる）を別の flag で残す

割り込まれないパーティションの名前:

- 案 E（採用）: `timed` に変える
- 案 F: `urgent` のまま意味を広げる

`--timed` と `-c` の組み合わせ:

- 案 G（採用）: 許さない（エラー）
- 案 H: 許し、TIME 行に `-c` の印を付ける

`slurm-history.sh` の表に入れるジョブ:

- 案 I（採用）: `timed` のジョブと、割り込みを入れる前（2026-10-23 より前）に終わったジョブだけ。`sacct` の照合は消す
- 案 J: `main` のジョブのうち、止められなかった（`sacct` の `Suspended` が 0）ものも入れる。`sacct` の照合を残す

## 決定と理由

採用: 案 A、案 E、案 G、案 I。

これは ADR-0052 の「急ぐジョブを `--urgent` で `urgent` に投げ、`main` のジョブを止める」部分と、時間を記録する測定も止め
られうるとした部分（案 H、TIME 行の印を止められたときだけ付け、`slurm-history.sh` が `sacct` で止められたジョブを除く）を
置き換える。また ADR-0029 の「排他のジョブの TIME 行は変えない」部分と、帰結の「時間を記録する測定の予定があるときは、
排他でない長いジョブを入れない」部分を置き換える。ほかの部分（割り込みの仕組み `partition_prio` と `SUSPEND,GANG`、
`OverSubscribe=FORCE:1`、メモリを数えない `CR_Core`、`-c` の投げ方と印）は変わらない。

ADR-0052 が案 I（測定を割り込めなくする）を退けた理由は、「長いジョブの多くが測定なので、急ぐジョブがそれを待つ」だった。
この ADR では、急ぐ短い計算も測定と同じ側（`timed`）に置き、割り込む相手は時間を記録しない `main` のジョブだけになる。
急ぐ計算が `timed` の長いジョブを待つことは、下の帰結で受け入れる。

### 設定（`modules/slurm/common.nix`）

```text
PartitionName=main  Nodes=r995 Default=YES MaxTime=INFINITE State=UP OverSubscribe=FORCE:1 PriorityTier=1
PartitionName=timed Nodes=r995 Default=NO  MaxTime=INFINITE State=UP OverSubscribe=FORCE:1 PriorityTier=2 PreemptMode=OFF
```

`urgent` の行の名前だけを `timed` に変える。名前を変えるのは、`squeue` のパーティションの欄（ADR-0052 で足した `%P`）を
読む人が、時間を記録するジョブを「急ぐジョブ」と読み違えないため。slurm.conf が変わるので、反映の `switch` で slurmctld と
slurmd が再起動する（背景）。反映の時点で `urgent` に待っているか走っているジョブがあると、パーティションが消えて
そのジョブは走れないので、`urgent` のジョブが無いときに反映する。

### `slurm-run.sh`

- `--timed` は `--partition=timed` を渡す。`--urgent` は消す（使っていたのは ADR-0052 からの 1 日で、利用者は 1 人）
- 知らないオプション（`-` で始まる語）は、ジョブの名前と読まずにエラーにする（消した `--urgent` を渡したときに、使い方の
  エラーより先に原因を示すため）
- `--timed` と `-c` は一緒に使えない（案 G）。`--timed` のジョブは排他で、ノード全体を取り、走っている `main` のジョブを
  すべて止める
- TIME 行: `--timed` でないジョブには、止められなかったときも常に
  `preemptible: 割り込まれうるので時間は記録に使わない（記録するなら --timed）` を足す。止められていなくても、いつ
  止められてもよい条件で走ったジョブで、同じ条件（割り込まれない）で測った値ではないため。印は止められたかの判定に
  よらないので、付け忘れたジョブの時間は、止められていなくても印で分かる
- `SuspendTime` の判定（ADR-0052 の `suspended:` と `suspended=unknown` の印）は残す。読むのは同じ `scontrol show job` の
  出力で、追加の呼び出しは無い。`timed` のジョブには付かないはずの印で、付けば設定か運用（`scontrol suspend`）の誤りを
  その場で示す。`main` のジョブでは、経過時間が延びた理由を示す

### `slurm-history.sh`

- 表と集計に入れるのは、jobcomp の `Partition` が `timed` のジョブと、割り込みを入れた日（2026-10-23、ADR-0052）より前に
  終わったジョブ（割り込みが無く、`main` の排他のジョブは止められえなかった）。それより後に終わった、`timed` でない
  ジョブ（`main`、ADR-0052 の `urgent`）は、件数を `UNTIMED: <件数>` で示して表から除く
- `sacct` の照合と `SUSPENDED:` の行は消す。`timed` のジョブは割り込まれず（`PreemptMode=OFF`）、`main` のジョブは
  止められたかによらず除くので、照合の結果で表が変わらない。照合は slurmdbd の記録の遅れ、番号の再利用、時刻の書式の
  ずれで失敗しうる部品で、それを残す理由が無い
- 割り込みの後に終わった行に `Partition` が無ければ、どちらに入れるか決められないので、読めない行として止まる

### 帰結

- 良い点: 時間を記録するジョブは、待っている `main` のジョブより先に走り、走っている `main` のジョブを止めて始まり、
  自分は止められない。投げる側は自分のジョブの性質を書くだけで、ほかのジョブを止める操作を選ばない
- 良い点: flag を付け忘れたジョブの時間は、TIME 行の印と `slurm-history.sh` の `UNTIMED:` の件数に出て、黙って記録に入らない
- 良い点: `--timed` は排他だけなので、`slurm-history.sh` の表に `-c` のジョブが混ざらない（ADR-0029 の帰結の、
  名前の `-shared` で分ける運用は、割り込みの前のジョブにだけ要る）
- 悪い点: `timed` のジョブどうしは割り込まない（同じパーティション、`PreemptMode=OFF`）。長い `timed` のジョブ（本番の燃焼の
  3 時間など）が走っている間は、高速化の測定も急ぐ短い計算も待つ。待っている `timed` のジョブの順は `--top` で変えられる
  （`scontrol top` は同じパーティションの中で並べ替える。ADR-0052）
- 悪い点: `--timed` は待っている `main` のジョブを追い越すので、時間を記録しないジョブにまで付けると、`main` のジョブが
  待ち続ける。付けるのは時間を記録するジョブと、数分の急ぐ計算だけにする（スキル slurm-run）
- 悪い点: 時間を記録しない `main` のジョブ（テーブル作成など）の見積もりの実績は、`slurm-history.sh` の表に入らない。
  `sacct` の `Elapsed`（止められていた時間を除く。ADR-0052）で読む（スキル slurm-run の `sacct` の例）
- 悪い点: `--timed` のジョブは、止めた `main` のジョブとメモリを分け合う（Slurm はメモリを数えない。ADR-0052）。
  `--urgent` より頻繁に使うので、投げる前に走っているジョブのメモリを見る回数が増える。止めたジョブのメモリが
  測定の時間に響くか（ページキャッシュの追い出しなど）は確かめていない
- 悪い点: 止められた `main` のジョブが持つロック（cargo のビルドディレクトリ、DVC のロック）を `timed` のジョブが待つと、
  互いに待ち続ける（ADR-0052 の帰結）。同じ worktree で `main` のジョブを実行したまま `--timed` で投げない
- ADR-0029 の帰結の「排他のジョブは、ノードに走っているジョブが 1 つもないときにしか始まらない」は、`main` の排他の
  ジョブにはそのまま成り立つ。`timed` のジョブは、走っている `main` のジョブ（`-c` のものも）を止めて始まるので、
  時間を記録する測定の予定があっても `-c` の長いジョブを入れてよい
- ADR-0030 の優先度（基礎 + 待った分 − nice）は、同じパーティションの中の順を決める。パーティションの間は
  `PriorityTier` が先に効き、`timed` の待っているジョブは `main` の待っているジョブより先に走る（ADR-0052）
- ADR-0041 の hook と `run-checks.sh` は、走っている排他のジョブ（`%h` が `NO`）を見る。`timed` のジョブは排他だけなので、
  走っている間は手元の全コアの計算を止める。`main` の排他のジョブ（時間を記録しない）の間も止めるが、守る記録は無い。
  判定を `timed` に絞るかは issue #458 で扱う
- 見直す条件: 時間を記録する長いジョブが測定を待たせることが続くとき（案 C の層を足すのでなく、長いジョブを `-c` で
  分けられるかから考える）

### 確認

- `.claude/tests/scripts/slurm-run.sh`: `--timed` が `--partition=timed` と `--exclusive` を渡すこと、`--timed` と `-c` が
  投げずにエラーになること、`--timed` でないジョブの TIME 行に常に `preemptible:` の印が付き、`--timed` のジョブには
  付かないこと、知らないオプション（`--urgent`）が投げずにエラーになること
- `.claude/tests/scripts/slurm-history.sh`: 割り込みの後に終わった `timed` のジョブと、その前に終わったジョブだけが表に入り、
  それ以外が `UNTIMED:` に数えられること、`sacct` を呼ばないこと
- 設定の構文: `nix build` で r995、t14g4、x1ng1 の toplevel を作る。2026-10-23 に、このブランチの 8bca06c8 で 3 つとも作れた。
  生成した slurm.conf は `PartitionName=timed … PriorityTier=2 PreemptMode=OFF` の行を持ち、`SLURM_CONF=<それ> scontrol show hostnames r995`
  が読めた。パーティションの行は slurmctld だけが解するので、反映後の確認で確かめる
- 反映後に r995 で確かめる（ユーザーと親のセッション）:
  - `scontrol show partition` が `main`（`PriorityTier=1`）と `timed`（`PriorityTier=2`）を出し、`urgent` が無い
  - 排他の `main` のジョブ（flag なし）を実行し、`--timed` のジョブを投げると、`main` のジョブが `SUSPENDED` になり、
    `timed` のジョブが走り、終わると `main` のジョブが `RUNNING` に戻る。`main` のジョブの TIME 行に `preemptible:` と
    `suspended:` が付き、`timed` のジョブの TIME 行には印が付かない
  - `slurm-history.sh` が、その `main` のジョブを表に入れず `UNTIMED:` に数え、`timed` のジョブを表に入れる
  - `timed` の排他のジョブの `squeue -o %h` が `NO` である（ADR-0041 の hook の判定）
  違えば、帰結を直す新しい ADR を書く

## 各案の長所と短所

### 案 B（ADR-0052 のまま）

割り込むことを投げる側が選ぶので、その操作は「走っているほかのジョブを止める」ことになり、許可の分類器に拒まれうる
（背景）。守りたいのは時間を記録するジョブなのに、それが止められる側にあり、止められたら再測定になる。

### 案 C（3 層）

`timed` の長いジョブの上に測定の層を置いても、その層が `timed` のジョブを止めれば、止められたジョブの時間は記録に
使えなくなり、`timed` を割り込まれないとした意味が無い。止めないなら、上の層の役は待っているジョブの順を変えることだけで、
それは `timed` の中の `--top` でできる。

### 案 D（`--timed` と `--urgent` を分ける）

`--urgent` を残すと、急ぐ計算を投げる側がまた「ほかのジョブを止める」ことを選ぶことになる（案 B と同じ）。急ぐ短い計算を
`timed` に置いても、止めるのは時間を記録しない `main` のジョブだけで、`timed` の中では投げた順（と `--top`）で走る。
分ける理由が無い。

### 案 F（`urgent` のまま）

slurm.conf を変えずに済み、反映でデーモンを再起動しない。ただし `squeue` のパーティションの欄に、時間を記録する燃焼や
測定が `urgent` と出て、何のパーティションかを読み違える。再起動は反映の 1 回だけで、走っているジョブは slurmctld と
slurmd の再起動を越えて続く（ADR-0052 の反映でも再起動した）。

### 案 H（`--timed -c` を許す）

`-c` のジョブの時間はほかのジョブと資源を取り合うので記録に使えず（ADR-0029）、時間を記録するための `--timed` と食い違う。
許す理由は、少ないコアで足りる急ぐ計算が、走っている `main` のジョブのうちコアの重なるものだけを止められることだが、
止められた `main` のジョブは終わりが遅れるだけで、急ぐ計算は数分なので、全部を止めても損は小さい。

### 案 J（止められなかった `main` のジョブも表に入れる）

`main` の見積もりの実績が表に残る。ただし `sacct` の照合（記録の遅れ、番号の再利用、時刻の書式で失敗しうる）を残す
ことになり、表に割り込まれうる条件のジョブと割り込まれない条件のジョブが混ざる。表の時間を記録にコピーする誤りを防ぐため、
表は `timed` に絞る。`main` の実績は `sacct` で読める（帰結）。

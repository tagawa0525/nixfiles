# ADR-0014: 崩れた日本語の語を、textlint と prh の辞書で pre-commit と commit-msg に検査する

## 背景

どのプロジェクトのセッションでも、日本語が同じ型で崩れる（2026-10-11 に調べた。#290）。

- 動詞の連用形をそのまま名詞にする: `確かめ`、`比べ合わせ`、`効き`、`数え`（本来は 確認、比較、影響、計数）
- 英語の直訳の造語: `端のケース`（edge case）、`作業木`（worktree）、`点断面積`（pointwise）、`掃引`（sweep）

ユーザーの発言（全セッションの記録を検索）に、和語に寄せる指示は無かった。原因の候補は 2 つ。

- 文書の多くを Claude が書いていて（xlc は 1649 コミット中 1567（xlc d260f722）、グローバルの CLAUDE.md は 20 回中
  19 回（nixfiles 245bc36）が Claude との共著。2026-10-11）、和語の動詞の多い文体で毎セッション読み込まれる。次のセッションがそれに寄せて書き、また
  文書に残る
- 指摘はプロジェクトごとのメモリに入り（nixfiles: `端のケース`、`作業木`。xlc: `点断面積`、`確かめ`）、ほかのプロジェクトの
  セッションには届かない

## 決定の要因

- 一度指摘された崩れは、どのプロジェクトのコミットでも二度と通らない（グローバルの hook が走るプロジェクト）
- 新しい崩れを 1 か所に足せば、すべてのプロジェクトに効く
- 動詞の「確かめる」と名詞の `確かめ` のように、前後の文字で見分けられる
- 既存のツールがあれば、それを使う

## 検討した案

- 案 A: textlint と textlint-rule-prh。辞書は prh の YAML（誤り、正しい語、JavaScript の正規表現）
- 案 B: Vale（Go のシングルバイナリ）
- 案 C: 辞書を埋め込んだ Rust の CLI を作る
- 案 D: 検査せず、グローバルの CLAUDE.md とメモリだけで伝える

## 決定と理由

採用: 案 A。

- textlint と prh は、日本語の文書の検査の事実上の標準で、nixpkgs にある（textlint 15.7.1、textlint-rule-prh 6.0.0。
  nixfiles の flake.lock の nixpkgs 18dd725c2960、2026-10-11。`textlint.withPackages` で組む）。Node.js の実行環境は Nix が持ち込む
- JavaScript の正規表現は先読みと後読みを書けるので、`確かめ(?=[のでを…])` のように、名詞の用法だけを止められる
  （2026-10-11 に、名詞の `確かめ` を止め、「確かめる」「確かめにくい」を通すことを確かめた）
- 案 B は、正規表現が Go の RE2 で先読みと後読みが無く、名詞と動詞を前後の文字で見分けられない
- 案 C は、辞書の形式と照合を自分で決めて保守する。既存のツールがあるので作らない（ユーザーの判断）
- 案 D は、プロジェクトごとのメモリが届かないという原因を残す

検査の範囲と置き場所:

- 辞書は `modules/home/parts/ja-terms/prh.yml`。textlint の設定（`@textlint/text` に足すコードの拡張子と、辞書の
  パス）は Nix で作り、hook は textlint と設定を Nix store のパスで呼ぶ
- 辞書に入れるのは、どの文脈でも 1 つの語に直せるものだけ（prh は 1 つの語にしか直せない）。`効き` は「影響」「効果」
  「効くか」のどれにもなり、nixfiles の ADR-0010 の「設定の効き」を「影響」にすると意味が変わるので入れない
- 崩れた語を例として書くときは、インラインのコードにする（textlint は Markdown のコードを検査しない）。崩れた語を
  わざと含むファイル（辞書のテストなど）は、リポジトリの `.textlintignore`（gitignore と同じ書き方）に挙げる。
  prh の辞書（`prh.yml`）は誤りを並べるので、どのリポジトリでも検査しない
- 名詞の用法を前後の文字で見分けるときは、名詞にしか続かない文字だけを使う。「に」「も」「は」、空白、行末は
  動詞にも続く（確かめにくい、確かめもせず、確かめはした、行の折り返しの `確かめ⏎る`）。「が」は、後に「たい」「ち」「てら」が続けば動詞（確かめがたい、確かめがち、確かめがてら）なので除く
- グローバルの pre-commit が、ステージしたファイルのうち Markdown、テキスト、コード（コメントと文字列の日本語を
  含めて、ファイルの全体）を検査する。対象の拡張子は `md`、`txt`、`rs`、`py`、`sh`、`nix`、`toml`、`yaml`、`yml`、
  `json`（大文字と小文字を問わない。自分のプロジェクトで日本語を書く言語。足すときは `git.nix` の一覧に足す）。
  symlink は行き先が文章でないので外す
- 見るのはコミットに入る中身（ステージした版）。Markdown の自動修正は作業ツリーをステージし直す（#282）ので、
  既定の検査の最後に実行する。手順は `modules/home/parts/ja-terms/staged.sh`。textlint は引数をグロブとして読み、
  エスケープも効かない（2026-10-11 に `[draft].md` で確かめた）ので、ブロブを番号の名前で書き出して検査し、
  出力を元のパスに戻す
- プロジェクトがローカルの pre-commit（`.git/hooks/pre-commit`）を持つときは、ほかの既定の検査と同じく走らない
- グローバルの commit-msg が、Claude Code のセッションのコミットの本文を検査する。除くのは `commit -v` の scissors の
  行から後だけ（`#` で始まる行は、`-m` や `-F` ではコミットに残る）。Merge、fixup、squash、Revert は、件名が元の
  コミットからコピーしたもの（Merge は git が作るもの）なので、件名を除いた本文だけを見る。textlint の起動は重いので、
  Conventional Commits と件名の長さの検査の後に呼ぶ
- upstream リモートのある fork では、ほかの検査と同じく飛ばす（上流の文書はこちらの辞書の対象でない）
- グローバルの CLAUDE.md に、技術文書で定着した語で書くことを肯定の形で 1 行足す（辞書は既知の崩れしか止めない
  ので、新しい崩れを減らす指針は残す）
- 言葉づかいのプロジェクトごとのメモリは、中身を辞書に移して消す

### 帰結

- 良い点: 一度辞書に入れた崩れは、どのプロジェクトのコミットでも止まり、直す語が示される
- 悪い点: 辞書に無い新しい崩れは止まらない。見つけたら辞書に足す。文脈で直す語が変わる崩れも止まらない
- 悪い点: 辞書を厳しくすると、その語を含むファイルを触るコミットが止まる。今ある文書は、辞書を足したときに各リポジトリで
  一度掃除する
- 悪い点: Node.js の実行環境が依存に入る（Nix が持ち込むので、手で入れるものは無い）
- 実装が決定に追いついていない点: 各リポジトリの今の文書の掃除（2026-10-11 の検査で lsp-det 4 件、nucrawler 4 件。
  nixfiles と xlc は 0 件）と、言葉づかいのプロジェクトごとのメモリの整理は、この変更を rebuild で反映した後に行う（#290）

### 確認

- `modules/home/parts/tests/ja-terms.sh`: 辞書の各項目が名詞の用法を止め、動詞（行の折り返しを含む）を通す。
  コードのコメント、ステージした中身だけを見ること、グロブの文字・空白・大文字の拡張子を含むパス、名前の変更、
  symlink とサブモジュールと辞書と `.textlintignore` のファイルを外すこと、fork で飛ばすこと。コミットの
  本文は、`#` で始まる行も見て、scissors の後と、fixup のコピーした件名は見ないこと
- 辞書の各項目の `specs`（prh が辞書を読み込むときに確かめる）

## 補足

- 2026-10-12: Markdown の自動修正は、ステージした版にだけ当て、作業ツリーをステージし直さなくなった（ADR-0028）。
  決定と理由の「Markdown の自動修正は作業ツリーをステージし直す（#282）」は、その前の挙動
- 2026-10-21: 辞書に、ADR 38 本とコミットメッセージの履歴から拾った語（`前付け`、`包み`、`拾う`、`抜け`、
  `突き合わせ`、`始まりの見込み`、`雛形`、`写す`、`終端子`ほか）と、表記ゆれ（`全て`、`付き`、
  `シンボリックリンク`）を足した。辞書に合わせて、確定済みの ADR を含む既存の文書の語を直した。確定済みの ADR の本文を
  直さないのは、決定の経緯を消さないためで、語の統一はそれを損なわないというユーザーの判断による。直したのは語だけで、
  決定と理由は変えていない。adr スキルの「確定した後に直してよいこと」に、意味を変えない語の統一を足した。
  design-records の「確定済みの本文を変えた」warning は、この直しによるもので、無視してよい
- 同日: 「配備」「幻覚」「退行」は、PR #228 で直した語だが、人員の配備や医学の退行のような別の意味があり、
  「効き」と同じく 1 つの語に直せないので辞書に入れなかった（一度入れて、ローカルのレビューで外した）。
  「付き」と「抜け」は、除外する語を列挙する書き方だと複合動詞（追い付き、引き抜け）の誤検出が続いたので、
  止める直前の文字を限る書き方にした
- 2026-10-21: チャットは口語でよいが、文書は文語的に書く、とユーザーが決めた。口語の動詞（`走らせる`、`見張る`、
  `燃やす`、`使い回す`、`測り直す`）と和語の名詞（`道具`、`鎖`、`乱数の種`、`閉包`、`確率表`、`直し方`、`釣り合い`）を、
  技術文書の語（実行する、監視する、燃焼させる、再利用する、再測定する、ツール、チェーン、シード、クロージャ、
  確率テーブル、修正方法、バランス）に直す項目を辞書に足した。活用のある語は、活用の形ごとに規則を分け、別の意味の
  語（小道具、連鎖、花の種、釣り合う）は specs で通す。「枠」は xlc の支持格子の意味の形（`枠あり`、`枠なし`、
  `枠のリング`、`枠の物質`、`枠を入れ`、`枠による`、`枠のある`、`枠を足す`）に限り、`DVC の段階` はステージにする。
  `見張らない` は「監視さない」でなく「監視しない」、`見張らず` は「監視せず」に直す。コピーの意味の「写し」は、
  先に足した規則にある。既存の文書は textlint の `--fix` で直し、取りこぼした形は手で直した
- 2026-10-21: バランスの意味の名詞の規則が、読点、「や」「と」、括弧、句点の前の名詞を通していた。続く文字の列挙に
  それらを足し、読点は前が「の」のときだけ止め、「不」の付く形容動詞を除いた。途中で、既定で止めて連用形に続く形
  （やすい、にくい、ながら、ます など）を除く書き方も試したが、ローカルのレビューで「〜ません」「〜づらい」「〜得る」
  「〜かねる」、行の折り返しを止める反例が出た。除く形が列挙しきれないのは「付き」「抜け」と同じなので捨てた。
  残る取りこぼし（「〜まで」「〜だ」の前の名詞）は、文脈で直す作業に任せる
- 2026-10-23: wall-clock time の直訳（`壁時計`、`壁時計の時間`、`壁時計時間`、`壁時計で測った時間`）を「経過時間」に直す規則を足した
  （ユーザーの指摘。xlc の ADR、issue、コードのコメントに 8 箇所あり、xlc 側で直した）。「実時間」「ウォールクロック」でなく
  「経過時間」にしたのは、xlc の記録で既に使われている語のため。時計そのものの意味（`壁時計の時刻`、`壁時計を見る`、`壁時計の針`、
  `壁時計を合わせる`、`壁時計が遅れる`、`壁時計の遅れ`、`壁時計を進める`）は通す。行の折り返しは除外（消費しない位置）だけで許し、
  「壁時計⏎の時間」は置き換えが 2 行を結合するか「経過時間の時間」になるので通して手で直す。nixfiles の slurm-history.sh の
  `同じ時刻帯の壁時計なので` は時刻（タイムスタンプ）の意味なので、`同じ時刻帯なので…実績（経過時間）を求める` に書き直した
- 2026-10-23: DVC とパイプラインのステージを別の語で書く形（ユーザーの指摘。この ADR の 2026-10-21 の補足で `DVC の段階` を
  ステージにし、xlc の CLAUDE.md と記録もステージで書いている）のうち、DVC の文脈で決まる続き（`段階を流す`、`段階を投げる`、
  `段階を再実行`、`段階が走る`、`段階は走らない`、`段階が再実行`、`段階の deps`・`outs`・`cmd`・`md5`。動詞の前の「1 本ずつ」
  「すべて」「再度」を許す）を止める規則を、`DVC の段階` の規則と 1 つにした。名前の形で判定する案は、インラインコードの名前
  （`` `xs-range` の段階 ``）に効かず、日付や ADR の番号の後の「段階では」を止めるので捨てた。「上流の段階」「段階の出力」は
  手順の意味（設計の上流の段階、前の段階の出力）と分けられないので入れず、手で直す。手順の段階（次の段階、前の段階、この段階、
  最終段階、現段階、初期段階、PR の段階）と数の後（2 段階の手法、二段階、2 つの段階）は通す。行の折り返しは消費しない位置で許す。
  xlc には規則に当たる箇所が約 90 箇所あり、進行中のブランチのマージの後に、手で直す形と合わせて直す

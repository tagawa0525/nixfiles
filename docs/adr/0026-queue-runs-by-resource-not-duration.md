# ADR-0026: Slurm に流すかを、かかる時間でなく占有する資源で決める

## 背景

`.claude/CLAUDE.md` は、Slurm の待ち行列に流す重い計算を「全コアを使うもの、目安で 1 分以上かかるもの」としていた。
時間の目安に当たるというだけで、1 コアで 2 分ほどの hooks-diff の比較（ADR-0024）を待ち行列に入れ、別のセッションの
1.5 時間の計算の後ろで待たせた（2026-10-11）。待ち行列の役目は、`--exclusive` で 1 本ずつ流して、計算資源の奪い合いと、
時間を記録する測定の乱れを防ぐことにある（ADR-0007）。1 コアの処理はそのどちらにも当たらない。

## 検討した案

- 案 A（採用）: 占有する資源で決める。多くのコアを長く使うもの、メモリを大きく使うもの、時間を記録する測定を流し、
  1 コアの処理と数分のビルドは手元で走らせる。時間を測るジョブが走っている間の、手元の数分の全コアのビルドは気にしない
- 案 B: 案 A に加え、時間を測るジョブが走っている間は、手元で全コアを使わない（`squeue` で確かめてから走らせる）。
  測定の乱れは減るが、長い測定の間は、ビルドを含むチェックも PR も止まる。数分のビルドの乱れは、測定の誤差としては小さい
- 案 C: 時間の目安を残し、1 分を延ばす。1 コアで長い処理（テストの全体、比べる道具）を待ち行列に入れる誤りは残る

## 決定と理由

案 A を採る。次のどれかに当たるものを、Slurm の待ち行列で 1 本ずつ流す。

- 多くのコア（目安で半分以上）を、5 分以上使い続ける（モンテカルロ、核データの一括処理、ライブラリの作り直し、
  集合体以上の格子計算、大きなベンチマーク）
- メモリを大きく使う（目安で搭載量の半分以上）
- 時間を記録する測定（短くても）

1 コアの処理（テスト、lint、比べる道具）は、時間がかかっても手元で走らせる。数分の nix build や cargo build も手元でよい。
目安は、r995 の搭載量に対する割合（コアの半分、メモリの半分）と 5 分で書き、構成が変わっても書き直さずに済むようにする。

### 帰結

- 時間を測るジョブの間に手元でビルドすると、その測定に数分の乱れが入りうる
- 目安に当たるかを、投げる前に見積もる必要がある。迷ったら流す（待つだけで、誤りにはならない）

# ADR-0042: hook は独自の手順のルール、うっかりミス、lint と fmt を、モデルが普通に書く形で守らせ、作為的な抜け道は塞がない

## 背景

claude-hooks（`modules/home/parts/claude-hooks`）の役割の範囲を書いた ADR は無く、ADR-0020 の「見落としたら止める
側に倒す」と、それを広げた ADR-0025（`bash -c` を深さ 5 まで読む、包みをほどく、決まらない形を止める）が基準に
なっていた。

2026-10-20 から 21 にかけて、hook のルールを直す 2 つのブランチでレビューの周が終わらなかった（2026-10-21 00:05
JST に `git log --oneline origin/main..<ブランチ>` と `git diff --stat origin/main...<ブランチ>` で数えた）:

- fix/pre-pr-create-accept-chained-push（#388、PR #402。先端 4389025）: 27 コミット、+665 行。ローカルのレビューは
  6 周目に入った（周の数は担当のセッションの記録による）
- feat/hook-require-pipefail（先端 2d05c00）: 14 コミット、+981 行。3 周目

レビューのたびに、作為的な書き方での抜け道が「正しい反例」として指摘され、ADR-0025 の基準では直す対象になった。

ユーザーの言葉（2026-10-21）: 「独自ルールを守らせること（WTを分けたり、no-ffでリベースし直すなど）、
うっかりミスやlint, fmtをしっかりかけるぐらいで、LLMの抜け道を塞ぐことではないです」「OpusやSonnetの判断は
ある程度信じることにしていた」。

## 検討した案

- 案 A: hook は普通に書く形で守らせ、作為的な抜け道は塞がない
- 案 B: ADR-0020 と ADR-0025 の基準のまま、見つかった抜け道を直し続ける
- 案 C: 抜け道を塞ぐ範囲を、ルールごとの ADR で個別に決める

## 決定と理由

採用: 「案 A」。

- 止めるもの: このリポジトリ独自の手順のルール（worktree を分ける、rebase したうえで no-ff でマージする、PR の形
  など）を守らせること、うっかりミス、lint と fmt を確実にかけること
- 判定の対象: モデルが手順に沿って普通に書く形のコマンド
- 止めないもの: 普通に書く形でない、作為的な書き方での抜け道（ラッパーで包む、文字列にして実行させる、珍しい
  git の設定や全体オプションで行き先を変える、など）。hook は境界ではなく、その穴はモデルの判断と人のレビューに任せる
- 新しいルールや判定を直すときは、普通に書く形で正しく動くことをテストで示す。それ以上の形は追わない
- レビューで出た「この形なら抜ける」という指摘は、普通に書く形でなければ直さず、この ADR を理由に閉じる。
  止める側の誤判定（普通の形を誤って止める）は直す
- ADR-0020 と ADR-0025 の「見落としたら止める側に倒す」方向を、今後は広げない。すでに入っているコードは消さない
  （消す手間と壊す危険の方が大きい）。簡単にしてよい箇所は #405 に洗い出す

案 B は、抜け道を 1 つ塞ぐと読み方が増え、その隙が次の反例になるので周が終わらない。案 C は、レビューのたびに
ルールごとの範囲を決め直すことになり、同じ問題が残る。

### 帰結

- hook のルールを直すブランチは、普通に書く形のテストで終わる。作為的な書き方をすれば hook を通り抜けられる
- 両 ADR は一部だけを置き換えるので `status: accepted` のまま、補足からこの ADR を指す
- 背景の 2 つのブランチは、この ADR を元に最小の形で作り直す（別の PR）

### 確認

レビューの打ち切りの基準（`.claude/skills/` の gh-pr-review、gh-pr-create、delegate、git-merge）がこの ADR を指す。

# ADR-0077: 外側と同じ区切りのヒアドキュメントを本文に書き、外側を途中で終わらせたコマンドを止める

## 背景

bash はヒアドキュメントの本文を、演算子の行の次の行から、区切りだけの行の前までとする。本文の中で同じ区切りの
ヒアドキュメントを開き（`python3 - <<'EOF'` の本文に `cat > f <<EOF`）、その閉じの行（`EOF`）を書くと、外側の本文は
その行で終わる。外側の閉じのつもりで書いた行までの残りは、本文のつもりのまま、シェルのコマンドとして走る。

2026-11-06 09:31 JST に、xlc のセッションの担当（記録 `~/.claude/projects/-home-tagawa-github-xlc/19a8117a-5afe-4e17-adf9-13d6bed755c6/subagents/agent-a20845a3787b2dc3e.jsonl`、
timestamp 2026-11-06T00:31:32Z）が、`python3 - <<'EOF'` の本文の Python の文字列にテストのシェルを書き、その中に
`cat >"$WORK/fsmonitor.sh" <<EOF` … `EOF` を置いた。外側はこの `EOF` の行で終わり、続く `chmod +x "$WORK/fsmonitor.sh"`、
`git -C "$FSM" config core.fsmonitor "$WORK/fsmonitor.sh"` などが、テストの中でだけ値の入る `$WORK` と `$FSM` が空のまま
nixfiles の worktree で走った。結果に `chmod: cannot access '/fsmonitor.sh'` と `/projects/-a/memory/MEMORY.md` への書き込みの
失敗が出ている（`git config` の行はエラーを出していない。worktree の `.git/config` に入ったかは確かめていない）。

Claude Code の記録（`~/.claude/projects/*/*.jsonl` と `*/subagents/*.jsonl`、2026-11-06 時点）の Bash のコマンドのうち `<<` を
含む 17,353 件（重複を除く）を調べると、本文に外側と同じ区切りの開きがあるヒアドキュメントは 31 件あった。外側を途中で
終わらせたのは上の 1 件と、2026-10-05T15:32:12Z（`758d77a4-…`。`python3 - <<'EOF'` の本文の Python の文字列に
`git merge … -F - <<'EOF'` と閉じの `EOF`。Python が SyntaxError で止まり、残りの行がシェルで走った）、
2026-10-10T12:28:41Z（`2fcaa033-…`。`cat > SKILL.md <<'EOF'` の本文の文書に `-m "$(cat <<'EOF'` と閉じの `EOF`。残りが
シェルの構文エラーで止まった）の 3 件である。残りの 28 件は外側を書いた所で終えている:

- 25 件は文中の言及（依頼文や issue の本文の `` `cat <<'EOF' > msg.txt` ``、Python の `\n` で書いたテストの入力）で、
  内側の閉じの行が無い
- 3 件は行末で同じ区切りを開いた入れ子だが、内側の閉じが区切りだけの行でない（字下げした `EOF`、
  `EOF'''`）ので、外側を終わらせていない（2026-10-10T17:34:19Z、2026-10-11T04:23:04Z、2026-10-13T03:40:29Z）

claude-hooks（`modules/home/parts/claude-hooks`）の `src/shell.rs` は、ヒアドキュメントの本文を bash と同じ範囲で原文から
切り出す（`Shell::heredoc`）。tree-sitter-bash も 2026-11-06 の形を bash と同じに読み、外側の閉じのつもりの `EOF` の行を
コマンドにする。

## 検討した案

- 案 A: 本文の行が、外側と同じ区切りの開きで終わる（行末が `<<D`、`<<'D'`、`<<"D"`、`<<-D`）なら止める。上の記録では
  6 件を止め、外側を途中で終わらせた 3 件をすべて含むが、外側を終わらせていない 3 件（内側の閉じを字下げした、後ろに
  文字が続く）も止める。演算子の後ろにリダイレクトを書いた開き（`cat <<'EOF' > f`）で外側を終わらせる形を止めない
- 案 B: 本文の行のどこかに、外側と同じ区切りの開きがあれば止める。上の記録の 31 件をすべて止め、28 件は文中の言及か
  外側を終わらせていない入れ子
- 案 C: 本文に外側と同じ区切りの開き（行のどこでも）があり、かつ外側の閉じの行より後のシェルの行（後ろの
  ヒアドキュメントの本文と閉じを除く）に、前後の空白を除くと区切りだけの行が残る（外側の閉じのつもりで書いた行が、
  コマンドとして走る）なら止める。外側を内側の閉じで終えたときに限って、外側の閉じのつもりの行が残る。後ろの
  ヒアドキュメントは、閉じの後の原文の行から bash と同じ順に読む（開きのある行の次の行から、その区切りの閉じの行まで
  を飛ばす）
- 案 C1（案 C の最初の版。ローカルレビューの 1 周目で捨てた）: 閉じの後の原文を平らな行として、区切りだけの行が
  同じ区切りの開きより多ければ止める。後ろのヒアドキュメントの本文の区切りだけの行（Python の文字列の `EOF`、
  Makefile のタブで字下げした `EOF`）を余りに数えて止め、後ろのコミットの本文の言及（`` `cat <<EOF` ``）を開きに
  数えて余りを打ち消し、外側を途中で終わらせた形を通す（どちらもビルドしたバイナリで再現した）
- 案 C4（案 C の前の版。記録の周の指摘で直した。#615）: 区切りの語を、引用符の中でも空白とシェルの区切りの文字で
  切る。`<<'END MSG'` を `END` と読み、外側か後ろの区切りが `END MSG` の形を通す。`<<' X'` は語が `'` だけになり、
  引用符を外すと空で開きごと捨て、その本文の区切りだけの行を余りに数えて止める（`cat > a <<'EOF'` の本文に
  `cat <<EOF here`、閉じの後に `cat > b <<' X'` の本文の `EOF`）。説明を事実に合わせる案と比べ、コードを直す方を
  採った（ユーザー 2026-11-06 の判断の要約）
- 案 C3（案 C の前の版。Copilot のレビューで直した）: 閉じの後の行の開きの区切りを、英字か `_` で始まる語の頭
  （`[A-Za-z_][A-Za-z0-9_]*`）だけで読む。`<<123` の本文の区切りだけの行を余りに数えて止め、`<<END-MSG` を `END` と
  読んで閉じを探し続け、余った閉じを飛ばして通す。本文の中の開きは区切りごとに別の正規表現で、区切り全体の引用符
  （`'D'`、`"D"`、`\D`）だけを受け、`<<E'OF'` を数えなかった
- 案 C2（案 C1 の直しで試して捨てた）: 後ろのヒアドキュメントの範囲を、tree-sitter-bash の木の `heredoc_redirect`
  から取る。内側の閉じに文字が続く入れ子（`EOF''','''cat > f <<'EOF'`）の後ろのコミットの `$(cat <<'EOF' … EOF)` で、
  木は外側の本文を bash と違う所で切って後ろの開きを本文の中に入れ、その閉じの `EOF` を余りに数えて止めた
  （`.claude/tests/hooks.sh` の QUOTED_CLOSE）
- 案 D: 外側の閉じのつもりの行がコマンドになる（tree-sitter-bash の木に、区切りと同じ名前の引数の無いコマンドがある）
  なら止める。残りの行に複数行のクォートがあると、木はその行を文字列の中に入れ、2026-10-05 の形（Python の `'''` が
  残りに出る）でコマンドにならない

## 決定と理由

案 C を採る。上の記録の 17,353 件に当てて、外側を途中で終わらせた 3 件だけを止め、ほかの 28 件を止めないことを確かめた
（このブランチのコミット bfbb8a83 を `nix build .#claude-hooks` でビルドした版、2026-11-06。最初の版の案 C1 も同じ 3 件だった）。案 A と案 B は外側を終わらせていない入れ子と
文中の言及を止め、案 D は残りの行のクォートで外す。案 C1 と案 C2 は上の記録では外さないが、記録に無い形で外す
（検討した案）。

- 対象は、本文を決められるすべてのヒアドキュメント（コマンドの置換の中、`bash -c` の文字列の中を含む）。本文の範囲は
  `Shell::heredoc` と同じ（同じ行のもっと前にヒアドキュメントがあるもの、区切りの行が無いものは決めない）
- 開き（本文の中の同じ区切りの開きと、閉じの後の行の開き）は、`<<` か `<<-` と空白の後の語を区切りとし、語の中の
  引用符と `\` を外して読む。語は、単引用符の部分、二重引用符の部分、`\` と次の 1 文字、引用符の外のシェルの区切りの
  文字（空白、`<>;&|()` とバッククォート）でない文字の並びで、木の `heredoc_start` を読む `Shell::heredoc` と同じ区切りに
  なる（`<<'D'`、`<<"D"`、`<<\D`、`<<E'OF'`、`<<123`、`<<END-MSG`、`<<'END MSG'` は `END MSG`、`<<' X'` は空白と `X` の 2 文字（先頭の空白を残す）。このリポジトリの Markdown lint の自動修正が code span の先頭の空白を落とすので、言葉で書く）。
  here string（`<<<D`）は数えず、区切りが続く語（`<<EOFX`）は別の区切り。1 つの正規表現（`OPENER`）で読む
- 閉じの後の行は、開きのある行の次の行から、その区切りの閉じの行（`<<-` は
  行頭のタブを除く）までを飛ばし、残ったシェルの行のうち前後の空白を除くと区切りだけの行を探す。bash はその行を
  コマンドとして実行するので、閉じとして書いた形（`EOF`）でなくても（行頭のタブや行末の空白のある `EOF`）止める
- 同じ行のもっと前に here string（`<<<`）があっても本文を決める（here string は行を読まない。`Shell::heredoc` の判定で、
  ほかのルールの `-F -` の本文の読み取りも同じになる）
- 拒否の文言の「本文の中」は、本文の中の最後の開きの行（外側を終わらせた閉じに対応する開き）
- 拒否の文言には、外側の演算子の行、本文の中の開きの行、外側が内側の閉じの行で終わり残りがシェルのコマンドとして走る
  理由（本文のつもりの変数は外側のシェルでは空）、修正方法（外側の区切りを本文に出ない名前にする。例 `<<'PYEOF'`）を
  書く。PC 全体で読む文言なので ADR の番号は書かない
- エスケープは設けない（ADR-0023 の「機械で判定できる理由でエスケープが要るなら hook の不足」）。止めるときは、残りの
  行がシェルで走ることが決まっていて、外側の区切りを変えれば必ず直る

### 帰結

- 本文に同じ区切りの開きがあっても、外側の閉じのつもりの行が残らなければ止めない。外側の閉じのつもりの行を書き忘れた
  形（残りの行が区切りだけの行で終わらない）は止めない
- 閉じの後の行は引用符を見ずに読む。シェルの行の引用符の中の `<<D`（`-m "see <<EOF"`）は開きとして次の行からを飛ばし、
  外側の閉じのつもりの行を飛ばすと止めない側に倒れる。複数行の引用符の中の区切りだけの行は、止める側に倒れる。
  上の記録の 17,353 件には、どちらの形も無い
- 区切りだけの行が本文の中の開きと関係なく残る形（閉じを 2 度書いた）は、このルールの対象外

### 確認

- `.claude/tests/hooks.sh` の block-nested-heredoc-same-delimiter の項が、上の 3 件の形を縮めたものと、開き方の書き方
  （`<<-`、二重引用符、`\`、コマンドの置換の中）を止め、文中の言及、外側を終わらせていない 2 つの入れ子の形、違う区切りの
  入れ子、続くヒアドキュメントを通すことを確かめる。閉じの後のヒアドキュメントの本文を飛ばすこと（後ろの本文の言及で
  通さない、後ろの本文の区切りだけの行で止めない）、外側の閉じのつもりの行の後ろの空白、同じ行の前の here string、
  拒否の文言の開きの行も同じ項が確かめる
- 開きの判定（here string と続く語を数えない）と、閉じの後の行の読み方は `src/rules/block_nested_heredoc_same_delimiter.rs`
  のユニットテストが確かめる。開きの区切りが `Shell::heredoc` と同じになること（`<<'END MSG'`、`<<' X'`、`<<"a;b"` など）も、
  両方に同じ開きを読ませて同じテストのファイルが確かめる

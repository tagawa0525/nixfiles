# ADR-0023: hook のエスケープは理由を値に取り、スキルの手順には書かない

## 背景

claude-hooks の各ルールは、`ALLOW_UNREVIEWED_HEAD=1` のようにコマンドへ環境変数を付けると検査を外せる
（エスケープ）。2026-10-11 の PR #308 の作業で、ユーザーが「未レビューではマージしない」と決めた後に、
サブエージェントが `ALLOW_UNREVIEWED_HEAD=1` つきのマージを 2 回試みた（hook と Claude Code の分類器が止め、
実害は無かった）。読んでいた文書に、次の誘因があった。

- `/gh-pr-merge` と `/gh-pr-review` の SKILL.md に、エスケープを付けてよい条件が手順の一部として書かれていた
- `pre-merge-check` の deny 文言が「〜なら付けてよい」の条件を 3 つ列挙し、どれかに当てはめる読み方を誘った
- 親のエージェントがサブエージェントへの依頼文に「rebase 後は付けてよい」と書いていた

## 決定の要因

- エージェントは自律的に進めたい。承認を都度求める形には戻さない
- エスケープは、止められた時に初めて知る形にする。通常の一手に見える場所（手順、依頼文）には書かない
- 付けた理由が記録に残ること。「強い確信があれば」のような自己判定の条件は、確信していた今回には効かないので書かない
- 機械で判定できる理由でエスケープが要るなら、それは hook の不足（ADR-0021 の「rebase だけ」が前例）

## 検討した案

- 案 A: 値を理由の文字列にする。hook は長さだけを見て、中身は検査しない。スキルからエスケープと周回数の記述を消す
- 案 B: deny 文言とスキルの文言だけを直し、値は `1` のまま
- 案 C: 「強い確信がある場合にのみ使ってよい」と deny 文言に書く
- 案 D: CLAUDE.md に、承認が要る操作とそうでない操作の境界を書く

## 決定と理由

採用: 「案 A」。理由を言葉にせざるを得ない 1 拍が入り、理由はコマンドとして記録に残る。無意味な文字列で逃れることは
できるが、そこは信じる（ユーザーの判断）。

- 値の条件: 空白を全部除き、ASCII を 1、それ以外（日本語など）を 2 として幅を数え、6 以上。`1`、`true`、`force`、
  `allow`（幅 5 以下）は弾き、日本語は 3 文字から通す。`unicode-width` のような依存は足さず、ASCII か否かだけで決める。
  `0` と空は付けていないものとして扱う。同じ名前の代入が複数あれば、短い値が 1 つでもあれば短い扱い（後ろの代入で
  上書きできない）
- 空白は Unicode の空白（全角空白、NBSP を含む）を全部除く。内側の空白で幅を水増しできない
- `$VAR`、`$(…)`、`<(…)` のような展開と ANSI-C 文字列（`$'…'`）は、字面と渡る値が違い記録に残らないので、幅に
  数えない。展開を除いた字面だけで 6 以上なら通す（`"rebase のみ、PR #$N"` のように、番号などを展開で足せる）。
  バックスラッシュも数えない。git の hook は展開後の値しか見えないので、その検査を git に任せるリポジトリでも、
  字面が短く展開を含むエスケープは claude-hooks の側で止める
- 理由を求めるのは、そのルールが止める命令のときだけ。止めない命令に付いていても咎めない（`ALLOW_PROTECTED_PUSH=1
  git push origin feat/x` は今までどおり通る）。理由つきなら評価自体を飛ばす（gitleaks や gh を呼ばない）
- 短い値を拒むときは、本来の文言（何を止めたか、正規の修正方法）に「`ALLOW_…` には理由を記載してください」の行を足す。
  しきい値は明かさない（長さを書くと、その長さに合わせた無意味な文字列を誘う）
- git 側の pre-commit（`modules/home/parts/scan-staged-secrets.sh`。ADR-0015 の `ALLOW_SECRET_COMMIT`）も同じ規則で
  読む。2 つの層で規則が違うと、どちらかの形が通らなくなる
- deny 文言は「正規の修正方法 / 理由を値にして付ける / 機械で判定できる理由なら issue に書く」の形に縮め、
  「〜なら付けてよい」の条件の列挙をやめる
- スキル（`gh-pr-merge`、`gh-pr-review`、`gh-pr-create`、`git-push`、`git-merge`）からエスケープ名と周回数の記述を消す。
  `.claude/README.md` の hook 一覧（人が引く参照）には残す。ローカルレビューの周回は回数ではなく「その周に検証できる
  誤りが無ければ終わり」を終了条件にする（レビューは周ごとに新しい候補を出すので、指摘ゼロを待たない）
- `decide-next.sh` の `MAX_ROUNDS` は残す（自動レビューは周ごとに指摘を生み、止めないとクォータを使い切る）。
  上限到達時は、未レビューの変更を列挙して報告し、止まる（エスケープの案内はしない）

採らなかった案:

- 案 B: 文言を直しても、`=1` は反射で付けられる。何を考えて付けたかが残らない
- 案 C: 検証できない基準。今回のサブエージェントは `range-diff` まで取って確信していた
- 案 D: CLAUDE.md は最小限に保ち、hook が強制するルールは書かない方針（ADR-0006 の運用）に反する。境界は hook と
  スキルの側で示せる

### 帰結

- 良い点: エスケープの理由が Bash のコマンドとして会話と記録に残る。スキルを読んでも「付ければ通る」が見えない
- 悪い点: 短いが筋の通った日本語の理由（`差分同一` は幅 8 で通るが `確認済` は幅 6 で境界）が弾かれることがある。
  文言が「理由を記載」なので、少し長く書き直せば済む。既存の `ALLOW_X=1` の書き方はすべて止まる
- この長さの条件は品質のゲートではない。boolean 的な値を弾き、理由を記録に残すためのもので、中身は信じる。
  「短すぎる」として長さを上げても通る値の質は上がらず、しきい値を探る動機だけが増える
- 見直す条件: 無意味な値でのエスケープが繰り返し見つかったとき

### 確認

- `.claude/tests/hooks.sh` で、`=1` と幅 5 以下の値が「理由を記載」で止まり、幅 6 以上（空白を除く）が通ること、
  deny 文言にしきい値が出ないこと、各ルールの deny 文言が理由つきの付け方を案内することを確かめる
- `modules/home/parts/claude-hooks/src/shell.rs` の単体テストで幅の数え方を確かめる

# ADR-0034: Copilot への再レビューは、直前のレビューに High が残るときだけ依頼し、それ以外はローカルレビューで確かめて終える

## 背景

Copilot code review の消費が増えた。数値は GitHub の API（PR のレビュー、課金の明細）から 2026-10-12 に取った。

- 2026 年以降に push のあった個人のリポジトリで、Copilot のレビューは PR 1,521 件に 2,228 回。2 回目以降が 707 回（31%）
- 課金は 2026-06 からトークン量に基づく AI Credits になった。2026-10 は 12 日で 19,651 credits（定価 $196.51）で、
  9 月の 1 か月分（17,855）を超えた
- 1 回あたりの credits は 9/27 の 14 から 9/29 の 57 に上がった。GitHub が 9/28 にレビューの effort の既定を Lite から
  Balanced に変えたため（[changelog](https://github.blog/changelog/2026-10-02-copilot-code-review-api-support-and-new-default-effort-level)）。
  個人の設定（Copilot settings → Code review → Review effort level）を 2026-10-12 に Lite に戻した。設定の変更で、
  コードの変更はない
- `decide-next.sh` の周回の上限（5）は守られていない。2026-09-01 以降に作った PR のうち 23 件が 6 回以上レビューされ、
  数え直しの印はどれにも無い。上限は回数だけを見るので、価値の低い周も上限まで回る

2026-09-19 からのレビュー本文（`<!-- ccr-overview-v2 -->`）は、指摘ごとに重大度（High / Medium / Low）と、その回に
新しく出た指摘の印（`· New`）を持つ。前の周で見落とした、変わっていないコードへの指摘は「Previously missed」の節に
本文だけで出て、インラインのスレッドにならない（nucrawler #94、#91 で確認）。`decide-next.sh` の `UNRESOLVED` は
スレッドを数えるので、この節を数えていなかった。

直前のレビューの結果と、次のレビューで新しい High が出た割合（同じ PR の続く 2 回の組。v2 の本文だけ）:

| 直前のレビュー           | Lite: 組の数 | Lite: 次に新しい High | Balanced: 組の数 | Balanced: 次に新しい High |
| ------------------------ | ------------ | --------------------- | ---------------- | ------------------------- |
| 新しい High あり         | 36           | 28%                   | 95               | 54%                       |
| Medium まで（High 無し） | 36           | 8%                    | 86               | 19%                       |
| Low のみ                 | 9            | 11%                   | 22               | 5%                        |
| 新しい指摘なし           | 54           | 17%                   | 35               | 29%                       |

新しい High は、直前の指摘の重さより、その後に書いたコードから出ている。指摘が無かった周の次でも出る（追加の変更を
入れた周）。2 回目以降に出る High の例は nixfiles #273 で、`env` を塞ぐと `env -S`、それを塞ぐと `env -a` と
`bash -x`、と 1 周に 1 つずつ迂回が見つかった。直した差分と、同じ種類の穴が他にないかをローカルで見れば、
Copilot の 1 周を待たずに潰せる。

## 検討した案

- 案 A: 今のまま（新しい push は毎回 Copilot に出し、上限 5 周）。上の消費のまま
- 案 B: 周回の上限を 2〜3 に下げる。2 回目以降でも新しい High が出るレビューは Balanced で 30〜38%、Lite で 17% あり、
  回数で切るとそれを落とす。ADR-0004 でもコードの PR の再レビューまで減るとして採らなかった
- 案 C: Medium も再依頼の条件にする。Lite で Medium までの周の次に新しい High が出たのは 36 組のうち 8%。
  修正後のローカルレビューで拾える範囲と見て、条件に入れない
- 案 D（採用）: High が残るときだけ Copilot に再依頼し、それ以外はローカルレビューで確かめて終える
- 案 E: 自動レビューを OFF にし、初回も変更量などで要否を決める。effort を Lite に戻した後の初回は軽く、減る量は
  1 回目の約 14%（30 行未満の PR）。マージの判定（`pre-merge-check` の検査 8）は bot のレビューが 0 件の PR を
  「自動レビューの無いリポジトリ」とみなして検査しないので、OFF にすると判定が黙って緩む。別の決定として後で扱う
- 案 F: High を直した後も Copilot に出さず、ローカルレビューで終える。High の 28%（Lite）は次の周でも新しい High を
  生むので、High の後は Copilot に確かめさせる

## 決定と理由

案 D にする（ユーザーの判断）。

- **重大度は Copilot の High / Medium / Low に揃える**。ローカルの `/code-review` の指摘も同じ 3 段で数える
  （High: 誤動作、セキュリティ、データの破損、ゲートの迂回。Medium: 限られた条件の不具合、品質。Low: 表記、好み）
- **残っている High**: 直前の Copilot のレビュー本文で、開いている指摘（その回に新しく出たもの「· New」と、
  前の周から残っているもの）と「Previously missed」の節にある High の指摘。前の周から残っている High は、Copilot が
  まだ直っていないと見ているものなので、新しいものと同じく Copilot に確かめさせる。本文が v2 の形でない（旧い形、
  レビューの失敗）とき、重大度のアイコンの無い指摘があるとき（形が変わって数え落としうる）は分からないので、
  High があるとみなす。節は見出しの行（`<summary><strong>`）だけで分ける（指摘の題名に同じ語が入りうる）
- **Copilot に再依頼する条件**（どれか 1 つ）:
  - 直前のレビューに High が残る（分からないときを含む）
  - 直前のレビューより後に、ユーザーの追加の要望で周回を数え直した（`reset-rounds.sh` の印）。指摘への対応ではなく
    新しい仕事なので、Copilot に見せる
- **それ以外**は、Medium と Low を直し、ローカルレビューで確かめて終える。周回の上限（5）は、High が出続けるときの
  歯止めとして残す
- **ローカルレビューの記録**: Copilot に再依頼する前と、再依頼せずに終える前に、head をローカルの `/code-review` に
  かけ、結果を PR のコメント（`<!-- local-review sha=<head> high=<n> medium=<n> low=<n> -->`。件数は、その head で
  検証して正しいと判断した指摘の数で、decline した指摘は数えない。直したら直した head で回し直して記録する）に残す
  （`record-local-review.sh`。レビューした SHA を受け、PR の head と違えば記録しない）。High のある記録は
  レビュー済みとして数えない（High を直せば head が変わるので、その head には直していない High が残る）。同じ
  head の記録が複数あれば最後の記録で決め、push できないリポジトリ（上流の PR）には記録を付けない。`request-rereview.sh` は、head の記録が無ければ要求しない。記録はリポジトリに
  書き込める人のものだけ数える（`reset-rounds.sh` の印と同じ）
- **マージの判定**（`pre-merge-check` の検査 8）: 最後の push が Copilot のレビューを受けていなくても、直前の
  Copilot のレビューに High が残っておらず（分かる形で）、その後に数え直しの印が無く、最後の push で Copilot の
  チェックが失敗しておらず、head のローカルレビューの記録が
  あれば通す
- **受け入れる弱点**: Medium と Low の修正、その後の小さな変更は、Copilot のレビューを受けない。ローカルレビューの
  記録はエージェントの自己申告で、回したかを機械では確かめられない。記録の件数で、後から効果を測れるようにする

## 帰結

- Copilot の 2 回目以降は、High が残る PR と、数え直した PR に限られる。2026-09-19 以降の v2 のレビューで、
  直前に新しい High が無かった周は、Lite で 99 組、Balanced で 143 組あった
- 「Previously missed」の指摘を `get-latest-review.sh` が本文から取り出して見せる。スレッドが無いので返信と
  resolve はできず、対応は台帳に書く
- ローカルレビューの記録が PR に残るので、ローカルで見つけた件数と、その後に Copilot が新しく出した件数を同じ PR の
  中で比べられる

## 確認

- `.claude/tests/scripts/gh-pr-review.sh`: `get-latest-review.sh` の重大度の数え方（開いている指摘、解決した指摘、
  Previously missed、旧い形）、`decide-next.sh` の判定（残っている High、数え直し、ローカルレビューの記録の有無）、`request-rereview.sh` が
  記録の無い head で要求しないこと、`record-local-review.sh` のコメントの形
- `.claude/tests/hooks.sh` の pre-merge-check のテスト: 検査 8 が、High の残らないレビューの後のローカルレビュー済みの
  head を通し、残っている High、Previously missed の High、旧い形、数え直し、記録の無い head、前の head の記録、
  印を取得できないときは止めること。印は書き込める人のコメントだけを読むこと
- 本文の読み方は `get-latest-review.sh`（bash）と `pre_merge_check.rs`（`remaining_high`）の 2 か所にあり、
  共有できないため、それぞれのテストで同じ規則を確かめている（ADR-0004 の `docs/` の判定と同じ扱い）

## 補足

- 2026-10-12: 実装の途中で、ローカルの `/code-review` の指摘と、2026-09-19 以降の v2 の本文 694 件（GitHub の API から
  2026-10-12 に取得）を読んで、次の版を作り直した
  - 記録が、レビューした SHA を受けず、記録した時点の PR の head を書く版。レビューの後に head が動くと、
    レビューしていない head を記録する
  - 最初の節を開いている指摘とみなし、"resolved since last review" か "previously missed" を含む行（大文字と小文字を
    区別しない）で節を切り替える版。指摘の題名に同じ語が入ると、後ろの High を数え落とす。また 694 件のうち 318 件に
    ある「What changed in this PR」の節の箇条書きを指摘と取り違え、重大度が分からないに倒れる
  - 見出しに "open finding" を含む節だけを開いている指摘とみなす版。2026-09 の本文の見出しは「Open (N)」で
    （240 件）、その High を数え落とす
  - 節を `</details>` で閉じない版。節の後に付く箇条書きや `<summary>` を、その節の指摘と取り違える
  - High のある記録もレビュー済みと数える版。直していない High の残る head を、Copilot に出さずにマージできる
  - 記録の件数に、直した指摘を含める版。直した後の head に、直す前の head で見つけた High を書くことになり、
    High のある記録がレビュー済みと数えられないので、先に進めなくなる
  - アイコンの無い指摘だけを「分からない」とする版。見出しや箇条書きの形が変わると、指摘を 1 件も拾わずに
    High を 0 と数える。知らない見出しの節と、開いている指摘の節の「- 」で始まらない行も分からないとした
  - 見出しの行（`<summary><strong>`）の形は変わらない前提の版。マークアップが変われば、どの節にも入らずに 0 と
    数える。知っている節の外のアイコン（要約の `**Findings:**` の行は除く）と、Previously missed の節の
    `<summary>` でない行のアイコンも分からないとした

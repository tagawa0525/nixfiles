# ADR-0018: 設計の記録の番号を git のタグで予約し、ぶつかった番号は design-records で振り直す

## 背景

`design-records new`（ADR-0009）は、ローカルの全ブランチの履歴と作業ツリーから次の番号を振る。これでは番号が
ぶつかる経路が 2 つ残る。

- 作ってからコミットするまでの間に、別のセッションが `new` を走らせると、同じ番号になる。2026-10-11 に xlc で
  ADR-0127 がぶつかった
- PR の流れ（別の clone、別のマシン）では、ほかの clone のブランチはローカルの履歴に無いので、数えられない

xlc の衝突は、マージのときに `cargo test`（crates/docs の検査）が見つけ、番号の振り直しはファイル名、表題、参照を
手で付け替えた。docs/issues の issue も同じ規則（全ブランチで最大の番号 + 1、使い回さない）で番号を振るので、
同じ衝突が起きる。

## 決定の要因

- 番号を決めることと予約することを 1 つの不可分な操作にする（compare-and-swap）。調べてから書くまでの間に
  ほかの人が割り込めない
- 予約の場所は、すべての clone から見え、main の履歴とブランチの保護を汚さない
- 予約が漏れて衝突したときも、振り直しを手作業にしない
- 番号は使い回さない（ADR-0009。古い参照が別の記録を指してしまう）

## 検討した案

- 案 A: 予約を main に直接 push する（予約のコミットを main に積む）
- 案 B: 予約だけを置く孤立したブランチ（`reservations` など）にコミットして push する
- 案 C: 注釈つきのタグ `adr-NNNN`（`issue-NNNN`）を打って push する

## 決定と理由

採用: 「案 C」。タグの作成は ref の作成なので、ローカルでは `git tag` が、リモートでは `git push` が、同じ名前が
既にあれば拒む。これがそのまま compare-and-swap になる。作業ツリーにもブランチの履歴にも何も足さない。

採らなかった案:

- 案 A: main への直接の push は、hook（`guard-git-push`、`block-main-commit`）と GitHub の branch protection で
  禁じている。予約のために例外を作ると、禁止の判定が複雑になる。main の履歴に、書きかけの記録（予約だけで
  終わったもの）のコミットが残る
- 案 B: チェックアウトしていないブランチにコミットするには、plumbing（`git commit-tree`、`git update-ref`）で
  コミットを組み立てる。push が拒まれたら（先に誰かが予約した）、fetch して積み直す手順が要る。タグなら 1 回の
  ref の作成で済む

### 予約（`new`）

`design-records new [--kind adr|issue] <slug> <title>` は、番号を決めたら注釈つきのタグ（メッセージは slug）を
既定ブランチの先端に打ち、`origin` があれば push する。push が拒まれたら（ほかの clone が先に予約した）、次の
番号でやり直す。`origin` に届かなければ、記録を作らずに止める（予約しないまま振ると衝突しうる）。`origin` が
無ければ、ローカルのタグだけで予約する。番号は、全ブランチの履歴、作業ツリー、その種類のタグのうち最大の番号

- 1 にする。

`origin` があれば、先に予約のタグを、次に origin の既定ブランチを fetch する。既定ブランチも取るのは、`prune` が
予約を解放した後の番号が、origin の既定ブランチの履歴にしか残らないため。タグを先に取るのは、ほかの clone が
マージを push してから予約を解放するため（後に取るブランチに、消えていたタグの記録が入っている）。タグは、
ローカルの既定ブランチでなく origin の既定ブランチの先端に打つ（まだ push していないコミットを、タグと一緒に
出さない）。

### 振り直し（`renumber`）

`design-records renumber [--kind adr|issue] <旧番号> [<新番号>]` は、このブランチで足した記録（既定ブランチとの
分岐点に無いもの）の番号を振り直す。新番号を省けば `new` と同じ規則で振って予約する。ファイル名と表題を変え、
このブランチで足した行の参照（ADR は `ADR-NNNN`、issue は `#NNNN`、両方の `NNNN-<slug>.md`）を付け替えて、
1 つのコミットにする。rebase した後の重複では、同じ番号の参照が 2 つの記録を指しているので、main から来た行の
参照は変えない（main の記録を指す）。既定ブランチにある記録の番号は変えない（既に参照されている）。

### 検査（`check`）

`check` は docs/issues の番号の重複も違反にし、予約のタグの slug と違う記録に注意を出す。issue の前付けと節の
形は検査しない（#270 で決める。それまで各リポジトリの検査に任せる）。

`check` は fetch しない。pre-commit で毎回のコミットに通信が入り、手元に通信が無いとコミットできなくなる。
rebase した後の番号の重複は作業ツリーのファイルどうしで見つかるので、タグが無くても `check` が示す。/git-merge
は rebase の直後に `check` を走らせ、重複があれば `renumber` で直す。

### 解放（`prune`）

`design-records prune` は、既定ブランチ（`origin` があれば origin の）の履歴に記録が入った予約のタグを、ローカル
と `origin` から消す。履歴に入った番号は、タグが無くても使った番号として残る。タグを消すのは、マージした記録
ごとにタグが積み上がり、`git tag` の一覧と fetch が記録の数に比例して重くなるため。履歴に無い記録（マージ
しなかったブランチのもの）のタグは、消すと番号が使い回されるので残す。`post-merge-cleanup.sh` がマージの後に
呼ぶ。

### CLI の形

種類は `--kind adr|issue`（省けば adr）で選び、サブコマンド（`new`、`renumber`）は ADR と issue で共有する。
今の CLI は `check --changed` のように、サブコマンドの後ろのオプションで振る舞いを変えている。`design-records issue
new` のように種類ごとのサブコマンドの木にすると、`check`、`status`、`prune`（種類を問わない）と形が揃わない。
issue の `new` は、表題の行（`# <title>`）だけを書く（前付けと節の形は #270 で決める）。

どのコマンドも、前に `-C <dir>` を付けると `<dir>` で走る（git の `-C` と同じ）。/git-merge は対象のブランチの
worktree を `git -C` で指して操作するので、`check` と `renumber` も同じ形で呼ぶ。

### 帰結

- 良い点: 同じ clone の並行したセッションと、ほかの clone やマシンの `new` が、同じ番号を振らない
- 良い点: rebase で見つかった重複を、`renumber` の 1 コマンドで直せる
- 悪い点: `new` が通信を要する。`origin` に届かなければ記録を作れない
- 悪い点: 予約だけして記録を作らずに終わった番号は、タグが残って欠番になる（使い回さない規則のとおり）
- 悪い点: 予約のタグの slug と違う slug でマージした記録（ファイル名の slug を後から変えた）のタグは、`prune` が
  消さない。`check` の注意で気づける
- 実装が決定に追いついていない点: 機能を足す前に作った記録（タグの無いもの）は予約されていない。ぶつかったら
  rebase の後の `check` で見つけ、`renumber` で直す
- 実装が決定に追いついていない点: レビューで見つけて見送った端の場合は、#314〜#319 に書いた

### 確認

確認は `modules/home/parts/design-records/tests/cli.rs` と `.claude/tests` のテストで行う。

## 補足

実装の途中で試して変えた版:

- **予約のタグの fetch に `--prune` を付けない版**: ほかの clone が origin から消したタグが手元に残り、`check` が
  注意を出し続けた
- **`--prune` を付け、排他しない版**: 同じ clone の 2 つのセッションで、push する前のタグを次のセッションの fetch
  が消し、両方が同じ番号を振った。予約と解放を clone の中で flock して 1 つずつ行う
- **リモートの予約を別の名前空間に取り、そこだけを prune する案**: 試す前に退けた。普通の `git fetch` が予約の
  タグを `refs/tags` に自動で取ってきて、消されずに残る
